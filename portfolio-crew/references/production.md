# 팀 제작 절차

## 여섯 서브 에이전트와 인계

신규 제작에서는 프로젝트 기록 목록과 디자인 방향을 확인한 뒤 아래 여섯 역할에 각각 서브 에이전트를 배정한다. 기존 포트폴리오 수정은 PM과 [변경 범위에 필요한 역할](routing.md#수정-종류에-따른-진행)을 배정한다. 제작 중 보완 작업은 진행 중인 담당자에게 수정 범위와 영향을 받은 산출물을 넘긴다. 메인 에이전트는 사용자와 승인 절차를 진행한다. 동시 실행 제한이 있으면 PM부터 시작해 의존 순서에 맞춰 배정한다. 서브 에이전트 생성 자체가 지원되지 않으면 제약을 설명하고 사용자에게 가능한 진행 방식을 확인한다.

| 서브 에이전트와 실무 지침 | 맡은 일과 넘길 산출물 |
| --- | --- |
| [PM](roles/pm.md) | 작업 계획, 단계별 완료 기준, 승인 기록, 실물 산출물 검토와 사용자 보고 |
| [웹 기획자](roles/web-planner.md) | 독자 과업, 사이트맵과 주요 탐색 흐름, 화면별 콘텐츠·상호작용 명세 |
| [콘텐츠 에디터](roles/content-editor.md) | 기록에 근거한 후보, 사용자 선택을 반영한 원고, 출처와 미디어 사용 조건 |
| [UI 디자이너](roles/ui-designer.md) | 실제 콘텐츠가 들어간 시안, 제작·내보내기한 이미지 에셋, 디자인과 모션 명세 |
| [프런트엔드 개발자](roles/frontend-developer.md) | 에셋·모션 브라우저 시험, 라이브러리 선정, 실행 가능한 정적 사이트와 빌드 결과 |
| [QA/배포](roles/qa-release.md) | 시안·브라우저 대조, 모션·로딩 검수, 결함 재검수, 승인된 배포와 최종 링크 확인 |

각 역할에는 해당 실무 지침의 경로, 승인된 입력의 위치, 편집 범위, 현재 단계, 산출물, 완료 조건과 수신 역할을 함께 준다. 서브 에이전트는 착수 전에 자기 지침을 읽고, 그 절차와 완료 기준으로 실제 작업을 수행한다. 파일 접근이 제한되면 필요한 지침과 자료를 작업 지시에 함께 전달한다. 인계를 받을 때는 산출물을 열어 확인하고, 빠진 자료나 다음 역할이 결정해야 할 내용을 발신자에게 회신한다.

웹 기획자와 콘텐츠 에디터는 서로 화면에 필요한 정보와 실제 근거를 확인한다. UI 디자이너와 프런트엔드 개발자는 구현 가능성과 시안 차이를 조율한다. QA/배포와 프런트엔드 개발자는 재현 결과와 수정본을 주고받는다. 에이전트 간 메시지를 사용할 수 있으면 직접 전달하고, 전달 기능이 제한되면 메인 에이전트가 답변까지 중계한다. 같은 파일을 다루는 작업은 편집 담당자와 순서를 정한다.

시안 단계부터 UI 디자이너·프런트엔드 개발자·QA가 [비주얼·모션 제작 가이드](visual-production.md)를 공유한다. 디자이너가 에셋과 모션을 명세하면 개발자가 실제 브라우저에서 작은 구현 예제를 만들어 결과를 돌려준다. 에디터는 자료 출처와 사용 범위를 확인하고, QA는 합의한 화면·모션 기준으로 검수 결과를 전달한다. PM은 참여 역할의 비교 자료와 남은 선택을 한데 모아 사용자에게 제시한다.

## 단계별 승인

PM은 신규 제작의 기본 단계를 사용해 산출물과 승인 지점을 계획한다. 기존 수정이나 제작 중 피드백은 아래 표에서 영향받은 단계와 범위를 선택한다. 단계가 끝날 때마다 메인 에이전트가 PM의 보고를 바탕으로 사용자에게 **실제 산출물, 확인한 내용, 남은 결정, 모션 제안 또는 승인 상태, 다음 단계**를 보여준다. 응답을 기다리기 전에 현재 산출물과 승인 항목을 진행 메모에 남긴다. 각 변경에 필요한 승인을 받은 뒤 다음 작업을 시작한다. 피드백이 오면 영향을 받은 결과물을 고쳐 다시 보여준다. [작업 경로 조정](routing.md#제작-중-경로-조정) · [진행 저장과 재개](continuity.md)

| 단계 | 사용자에게 보여줄 산출물과 받을 결정 |
| --- | --- |
| 계획 | 대상 독자와 목표, 배정 역할과 인계 순서를 보여준다. 신규 제작은 기획에 들어가기 전에 계획을 승인받는다. 기존 수정은 기준 버전과 변경·보존 범위를 보여주고 추가로 합의할 사항을 확인한다. |
| 웹 기획·콘텐츠 | 신규 제작은 사이트맵과 프로젝트별 추천 콘텐츠를 보여준다. 수정 작업은 바뀐 진입점·화면과 원고만 보여준다. 넣을 내용이 정해지지 않았으면 후보를 고르게 하고, 사용자가 지정한 문구나 선택은 그대로 사용한다. |
| UI 디자인 | 실제 원고와 사용할 에셋이 들어간 데스크톱·모바일 시안을 반드시 보여준다. 신규는 첫 화면과 대표 상세를, 일부 수정은 영향받은 화면을 보여준다. 주요 모션의 실행 예제나 조작 영상과 함께 적용할 효과와 피드백 반영 시안을 확인받는다. |
| 대표 흐름 구현 | 신규 제작이나 여러 화면에 바뀐 디자인을 확장할 때 대표 브라우저 미리보기를 보여준다. 시안과 에셋·크롭·동작을 비교하고 차이를 고친 뒤, 나머지 화면에 적용해도 되는지 확인한다. |
| 구현·QA | 실제 사이트 미리보기, 변경한 화면·동선의 검수 결과, 남은 제약을 보여준다. 게시가 필요하면 변경 내용, 공개할 파일·자산, 저장소·브랜치 또는 호스팅 위치와 접근 범위를 승인받는다. |
| 링크 검증 | 선택한 형식의 결과 링크를 제공하고, 접속 범위와 확인한 동작을 보고한다. |

### 사용자가 프로젝트 콘텐츠를 고르는 방법

신규 제작이나 프로젝트의 새로운 내용이 필요한 경우 해당 프로젝트의 후보에 번호를 붙인다. 서비스 소개, 개인 역할, 대표 기능, 기술 선택, 트러블슈팅, 검증 결과, AI 활용, 시연 등에서 기록이 뒷받침하는 후보를 뽑는다. 후보마다 화면에 들어갈 내용 한 줄, 추천 이유, 출처, 사용할 이미지나 자료의 공개 가능 여부를 표시한다. 중요도가 높은 몇 개를 추천하고 사용자에게 넣을 번호와 추가할 내용을 고르게 한다.

채택된 사례는 **내 역할 → 어려웠던 문제 → 내 판단과 작업 → 확인된 결과**로 편집한다. 팀 결과와 본인 작업을 구분하고 수치에는 비교 기준, 검증 환경, 표본이나 관찰 범위를 붙인다. AI 활용 사례는 AI에 맡긴 작업과 본인이 고치거나 검증한 내용을 연결한다. 발표·개발 기록이나 갤러리는 해당 주장 옆에서 확인할 수 있도록 배치한다.

### 모션 제안과 승인

각 단계에서 추가할 만한 모션이 있으면 화면과 목적을 설명한 뒤 제안한다. 사용자에게 트리거, 움직이는 요소, 대략적인 지속 시간, 모바일·축소 모션의 동작을 보여주고 적용할 효과를 고르게 한다. 실제 삽입은 효과별 승인 후 진행한다. 사용자가 시안 수정과 모션 선택을 함께 답하면 선택한 효과를 기록하고, 수정한 시안을 다시 보여주며 구현 승인을 받는다. 새 모션이 없는 단계에는 기존 승인 효과의 진행 상태를 보고한다. 승인된 효과를 바꾸거나 새로 추가할 때는 변경안을 다시 확인받는다.

프런트엔드에 인계할 명세에는 승인된 효과의 시작·끝 상태, 이징, 반복·역방향, 모바일·축소 모션 동작, 선택한 라이브러리와 로딩 방식을 적는다. 구현 후 실제 스크롤·클릭·터치와 라이브러리가 로드되지 않는 상황의 동작을 확인한다. [비주얼·모션 제작 가이드](visual-production.md#모션-방식과-의존성-선택) · [브라우저 검수 가이드](review.md)

## 최종 링크 제공

- **GitHub 블로그**는 승인받은 저장소와 브랜치에 사이트 파일을 푸시한다. 기존 게시 설정을 사용하고, 신규 사이트 또는 사용자가 승인한 설정 변경에만 게시 소스를 설정한다. 정적 파일을 브랜치로 게시할 때는 **Settings → Pages**에서 해당 브랜치와 사이트 폴더를 선택한다. 배포가 끝나면 실제 Pages URL, 상세와 에셋이 열리는지 확인한다. [GitHub Pages 게시 소스 설정](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)
- **HTML 링크**는 사용자가 승인한 접근 범위에 맞춰 미리보기나 승인된 호스팅에 정적 HTML을 제공한다. 공유 링크가 필요하면 호스팅 방식과 공개 범위를 승인 단계에서 정한다. 로컬 미리보기의 접근 범위를 명시하고, 공개 링크는 로그아웃 상태에서 열어 확인한다. 호스팅 접근이 막히면 열 수 있는 미리보기를 제공하고 공유 링크를 만드는 데 필요한 접근 권한을 안내한다.
