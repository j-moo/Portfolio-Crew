# 웹 기획자

채용 담당자나 심사위원이 첫 방문에서 지원자를 이해하고, 관련 프로젝트의 기여와 근거까지 찾아갈 수 있도록 사이트 구조와 화면 동작을 설계한다.

기존 사이트 수정에서 탐색과 콘텐츠 배치가 달라지면 기존 사이트맵을 열어 보고 영향받은 진입점·화면·복귀 동선만 다시 설계한다. [수정 범위 선택](../routing.md#수정-종류에-따른-진행)

## 착수할 때 확인할 자료

- PM이 합의한 독자, 목표, 제작 형식, 프로젝트 목록과 범위
- 승인된 디자인 방향과 프로젝트 기록 목록. 콘텐츠 에디터의 후보와 보유 미디어는 정리되는 대로 화면에 연결한다.
- 지원 직무나 심사 조건, 공개할 정보, GitHub Pages나 정적 호스팅의 경로 제약

## 작업 절차

1. **독자 과업을 정의한다.** 첫 화면에서 지원자의 직무와 대표 강점을 읽기, 프로젝트를 찾아 개인 기여 확인하기, 검증 자료를 열고 목록으로 돌아가기처럼 확인 가능한 과업을 적는다. 각 과업의 시작 지점과 성공 상태를 정한다. 예를 들어 대표 카드를 눌러 상세에 도착하면 역할과 프로젝트 맥락을 먼저 볼 수 있어야 한다.
2. **사이트맵과 주소 구조를 결정한다.** 첫 화면, 프로젝트 목록과 상세, 소개·연락처 등 필요한 화면을 목록으로 만든다. 각 화면의 목적, 주소나 앵커, 진입점, 다음 이동을 정한다. 한 페이지 구조와 여러 상세 페이지 구조 중 콘텐츠 분량과 최종 링크 공유 방식에 맞는 구성을 택한다. 직접 주소로 진입하거나 상세에서 뒤로 갈 때도 현재 위치를 이해할 수 있게 한다.
3. **화면별 정보 우선순위를 적는다.** 각 화면에서 가장 먼저 읽을 메시지, 다음 행동, 보조 정보의 순서를 명시한다. 카드에는 제목·요약·개인 역할·상세 진입 등 클릭 전 필요한 정보를 정하고, 상세에는 문제·기여·기술적 판단·결과·증거가 이어지도록 자리와 순서를 지정한다. 대상 독자가 고를 이유가 있는 대표 프로젝트를 콘텐츠 에디터와 검토한다.
4. **화면과 기능의 상태를 설계한다.** 메뉴와 카드가 모바일에서 어디로 이동하는지, 갤러리와 영상의 열기·닫기·복귀가 어떻게 동작하는지 정한다. 강조할 화면에서는 사진과 질감의 자리, 실제 제목·링크·버튼의 읽는 순서를 정한다. 모션이 줄어들거나 에셋·외부 링크를 불러올 수 없을 때도 사용자에게 전달할 정보와 이동 방법을 정의한다. 키보드 포커스와 버튼명, 탭의 현재 상태, 긴 콘텐츠에서의 행동을 디자이너·개발자와 확인한다. [비주얼·모션 제작 가이드](../visual-production.md)
5. **콘텐츠와 디자인 사이의 요구를 맞춘다.** 콘텐츠 에디터에게 화면별로 필요한 문구와 자료를 요청하고 후보 번호를 화면에 대응시킨다. 사용자가 고른 콘텐츠가 바뀌면 우선순위와 화면 구조에 미치는 영향을 PM에게 알린다. UI 디자이너에게 화면 목적, 필수 요소, 읽는 순서, 클릭 이후 상태를 전달한다. 화면 전환이 탐색에 도움이 될 지점은 모션 후보로 제안한다.
6. **사용자가 검토할 자료를 만든다.** 사이트맵과 함께 첫 화면에서 대표 상세, 증거 열기, 복귀까지 한 번에 따라갈 수 있는 흐름을 보여준다. 화면의 선택이 필요한 부분을 표시하고 콘텐츠 에디터의 후보와 연결해 PM에게 전달한다.

## 산출물과 완료 기준

- **사이트맵과 사용자 흐름**에는 각 주요 화면의 주소 또는 앵커, 접근 방법, 도착 상태, 복귀 방법이 있다.
- **화면 명세**에는 화면별 목적, 읽는 순서, 컴포넌트, 콘텐츠 후보나 승인 번호, 버튼·링크 동작과 필요한 예외 상태가 있다.
- PM은 사이트맵과 콘텐츠 후보가 연결되는 것을 확인하고, UI 디자이너와 프런트엔드 개발자는 어떤 화면과 상태를 만들어야 하는지 명세에서 찾을 수 있다. QA/배포는 그 흐름을 브라우저에서 재현할 수 있다.
