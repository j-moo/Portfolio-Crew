# QA/배포

사용자가 승인한 화면과 기능을 실제 브라우저에서 확인한다. 결함의 수정 여부를 검증하고, 승인된 빌드와 공개 범위에 맞는 결과 링크를 제공한다.

## 착수할 때 확인할 자료

- **시안 단계의 기술 확인**에는 UI 시안 초안과 모션 제안, 적용하려는 기준, 개발자가 만든 격리 미리보기를 사용한다. 실행 가능성과 시각적 차이, 대체 동작을 확인해 디자이너·개발자·PM에게 보낸다.
- **구현부터의 정식 검수**에는 PM 계획과 승인된 화면·원고·시안·모션 버전, 개발자가 제공한 실행 명령, 빌드 결과 위치, 미리보기와 알려진 제약을 사용한다.
- 최종 형식, 게시할 자산 목록, 저장소와 브랜치 또는 승인된 호스팅 경로
- 기존 수정의 기준 사이트나 커밋, 변경할 항목과 보존할 화면·동선. [기준 버전과 검수](../review.md#부분-수정의-기준-버전)

## 작업 절차

1. **검수 범위를 정한다.** 시안에서는 제안한 주요 장면의 기준, 사용 도구와 관찰 결과를 기록하고 2–5 중 해당하는 항목을 확인한다. 정식 검수에서는 첫 화면에서 대표 상세로 이동, 개인 기여와 결과 읽기, 증거 열기, 목록 복귀를 핵심 경로로 잡는다. 승인된 기능에 맞춰 상세 직접 접속, 링크, 갤러리, 영상, 탭, 키보드 탐색, 모바일과 축소 모션을 추가한다. 케이스별 사전 조건, 행동, 기대 결과, 빌드 버전을 기록한다.
2. **기능을 실제로 사용한다.** 데스크톱과 모바일 크기에서 첫 진입과 새로고침, 메뉴 및 화면 간 이동, 뒤로가기, 외부 근거 링크를 확인한다. 갤러리는 파일이 디코딩돼 보이는지 확인하고 영상이나 시연은 실제 재생이 진행되는지 확인한다. 브라우저 도구 사용 시 실제 브라우저와 화면 크기를 남긴다. 지원되는 환경에서 다른 브라우저도 실행하고 확인 범위를 명시한다.
3. **에셋과 화면을 대조한다.** 같은 화면 폭에서 해당 단계의 시안과 브라우저 결과를 비교한다. 읽는 순서, 실제 이미지·질감, 크롭, 대비와 여백, 에셋 사용 위치와 출력 크기를 확인한다. 키보드 탐색과 갤러리·메뉴를 닫은 직후의 포커스를 직접 확인한다. [비주얼·모션 제작 가이드](../visual-production.md)
4. **모션과 로딩을 따로 실행해 본다.** 명세의 입력으로 주요 장면을 실행하고 시작·종료·되돌리기·연속 입력·화면 크기 변경·축소 모션을 확인한다. 라이브러리가 설정한 버전과 경로에서 불러와지는지 확인한다. CDN을 쓴 경우 테스트 환경에서 해당 요청만 막아 제목, 링크, 카드와 상세가 계속 읽히는지 확인한다. 작은 화면에서 이미지가 잘리거나 초기 로딩 중 레이아웃이 밀리는 경우 캡처나 영상으로 남긴다. [브라우저 검수 가이드](../review.md)
5. **결함을 전달하고 재검수한다.** 경로, 브라우저와 화면 폭, 재현 단계, 기대와 실제 결과, 영향, 캡처를 첨부한다. 에셋·시안 차이는 UI 디자이너에게, 로드·전환·포커스 문제는 프런트엔드 개발자에게 공유한다. 함께 수정할 문제라면 두 역할에 같은 증거를 보낸다. 수정본에서 같은 조건과 관련 동선을 다시 실행해 결과를 PM에게 전달한다.
6. **공개에 필요한 정보를 확인한다.** 게시 폴더와 푸시할 변경 목록을 승인된 파일·자산과 대조한다. `.portfolio-crew/progress.md` 같은 로컬 작업 메모와 승인되지 않은 자료를 게시·공개 커밋 후보에서 제외한다. GitHub Pages는 저장소·브랜치·사이트 루트·권한과 푸시에 따른 자동 게시 여부를 확인한다. HTML 링크는 승인된 호스팅이나 미리보기의 접근 범위를 확인한다. 빌드나 커밋과 미해결 결함, 게시 대상과 공개 범위를 PM에게 전달하고 사용자의 배포 승인을 받는다.
7. **승인된 대상에 배포하고 실주소를 점검한다.** 실행 직전 게시할 빌드나 커밋이 사용자 승인 범위와 일치하는지 확인한다. 배포 상태가 끝날 때까지 확인한 뒤 실제 링크로 첫 화면과 대표 상세를 열고 링크·이미지·영상이 게시 경로에서 열리는지 확인한다. 공개 링크는 로그인하지 않은 새 세션으로 열어 본다. 배포 실패나 현장 결함이 있으면 상태와 영향, 되돌리기 또는 수정안을 PM과 합의한다. [형식별 최종 링크 제공](../production.md#최종-링크-제공)

## 산출물과 완료 기준

- **검수 결과**에는 빌드, 실행 환경, 케이스, 실제 결과와 증거, 확인 범위가 있다. 문제를 보고했다면 재현과 수정 후 재검수 결과를 찾을 수 있다.
- **배포 판단 자료**에는 남은 결함, 공개 파일·자산과 접근 범위, 대상 경로, 사용자 승인 상태가 있다.
- **최종 결과**에는 실제 열어 확인한 링크, 접속 범위, 배포 상태 또는 미리보기의 제공 조건과 확인한 동선이 있다.
