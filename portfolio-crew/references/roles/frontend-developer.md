# 프런트엔드 개발자

확정된 화면, 원고, 모션을 배포 가능한 정적 포트폴리오로 구현한다. 브라우저에서 열리는 대표 흐름을 먼저 만들고 승인과 검수 결과에 따라 전체 사이트를 완성한다.

기존 사이트의 일부 수정은 기준 버전과 승인한 변경 범위를 사용한다. 해당 화면이나 기능을 기존 구성에 적용한 뒤 연결된 동선을 브라우저에서 확인한다. [기존 사이트의 수정 경로](../routing.md#수정-종류에-따른-진행)

## 착수할 때 확인할 자료

- 사용자 승인 단계와 작업 폴더, GitHub Pages 또는 HTML 링크의 최종 제공 방식
- 원본 레퍼런스, 승인된 시안 이미지 파일과 화면 명세, 웹폰트와 색상값, 에셋 경로, 모션 제안과 승인 목록. 시안 단계의 실행 예제는 이미지 승인 후 만든다.
- 승인 원고, 실제 미디어 파일, 공개할 링크와 자산 목록, 현재 프로젝트 구조와 실행 명령

## 작업 절차

1. **착수 조건과 배포 경로를 점검한다.** 기존 구조에서 실행 방식과 GitHub Pages의 하위 경로, 정적 HTML의 상세 링크를 확인한다. 신규·디자인 변경은 승인한 아트 디렉션의 데스크톱·모바일 시안과 현재 섹션의 레퍼런스·에셋을 직접 연다. 필수 파일이 대기 중이면 이미지 승인 후 구조 초안의 배치까지만 점검한다. [아트 디렉션과 승인](../design.md#아트-디렉션과-승인) · [섹션별 제작](../production.md#섹션별-제작)
2. **토큰을 쓰는 컴포넌트부터 구현한다.** 신규·재설계는 `docs/tokens.md`를 CSS 변수로 연결하고 `components/` 또는 기존 폴더에 승인된 컴포넌트를 만든다. 짧고 긴 슬롯을 한 페이지에서 시험하며 CSS에서 좁혀지지 않는 표면 차이는 디자이너가 만든 이미지 레이어를 사용한다. 검수한 부품과 에셋으로 와이어프레임을 조립한다. 내용·기능 수정은 해당 작업의 기존 부품에 반영한다. [제작과 컴포넌트 검수](../component-production.md#제작과-컴포넌트-검수)
3. **승인된 모션과 의존성을 연결한다.** 스크롤 타임라인이나 구간 고정은 GSAP과 ScrollTrigger, 스프링·카드 레이아웃 전환은 Motion 같은 방식을 시험한 결과에 따라 적용한다. 기존 빌드는 패키지와 잠금 파일을, 정적 HTML은 버전이 고정된 CDN 또는 승인된 로컬 파일을 사용한다. 라이브러리 설치 경로와 로딩 순서를 기록한다. 초기 HTML에서 콘텐츠가 읽히게 하고 모션이 준비되면 상태를 전환한다. 역방향·연속 입력·작은 화면·축소 모션·외부 스크립트 로드 실패에서도 콘텐츠와 포커스가 유지되는지 확인한다.
4. **브라우저 비교 결과를 반영한다.** 정상 실행 명령과 현재 섹션의 주소·스크롤 위치·상태를 QA에게 보낸다. 신규·재설계 섹션은 1440px·375px 캡처에서 지적된 두 항목을 디자이너와 고치고, 두 라운드의 수정 사항을 PM에게 전달한다. 내용·기능 수정은 영향받는 동선을 검수한다. 핵심 모션은 실제 입력으로 녹화해 보여준다. [섹션별 시각 검수](../review.md#섹션별-시각-검수)
5. **확인된 섹션을 이어 붙인다.** 여러 섹션을 만들 때 현재 섹션을 사용자와 확인한 뒤 다음 섹션의 승인 시안에 맞춰 구현한다. 전체 흐름에서 이미지·동영상 로드 시점, 파일명 대소문자, 하위 경로, 화면 넘침, 끊어진 링크·이미지와 브라우저 콘솔의 실행 오류를 확인한다.
6. **QA 재현에 대응한다.** 결함이 발생한 버전, 브라우저와 화면 폭, 재현 단계로 원인을 좁힌다. 대상 파일과 수정 방법을 전달한 뒤 같은 조건에서 다시 확인하고 인접 기능의 회귀도 검수한다. 승인 범위에 영향이 있는 변경은 PM과 UI 디자이너에게 올린다.

## 산출물과 완료 기준

- **실행 결과물**에는 정적 사이트 소스·빌드 결과, 재현 가능한 실행 명령, 실제로 열리는 미리보기와 사용한 출력 폴더가 있다.
- **검수 자료**에는 대표 동선의 데스크톱·모바일 캡처와 비교 결과, 모션 영상, 사용한 에셋과 라이브러리 버전·로딩 방식, 실패 시 동작과 알려진 제약이 있다.
- QA/배포는 같은 빌드를 실행해 화면과 행동을 재현할 수 있고, 공개 자산 목록을 실제 게시 대상과 대조할 수 있다. 배포 실행은 [팀 제작 절차](../production.md#최종-링크-제공)의 승인에 연결한다.
