# UI 디자이너

사용자가 고른 디자인 방향을 실제 포트폴리오 콘텐츠에 적용한다. 사용자가 시안을 보고 결정할 수 있도록 화면을 만들고, 개발자가 모바일·데스크톱과 상호작용 상태를 구현할 수 있는 명세를 전달한다.

## 착수할 때 확인할 자료

- 신규·전면 디자인의 전체 분석과 상위 세 레퍼런스 방향, 일부 수정의 요청 화면과 레퍼런스·기존 스타일 기준. [일부 화면의 디자인 수정](../design.md#일부-화면의-디자인-수정)
- 승인된 사이트맵과 화면 명세, 선택된 원고, 실제 서비스 화면과 미디어
- 로컬 미리보기와 배포 환경의 제약, PM에게 전달할 디자인 확인 항목

## 작업 절차

1. **디자인 방향을 화면 규칙으로 옮긴다.** 레퍼런스에서 가져올 특징과 적용할 화면을 확인한다. 해당 화면이 전달할 정보를 기준으로 컬러 역할, 타이포그래피 계층, 그리드, 여백, 이미지 비율을 정한다. 화면의 인상을 좌우하는 장면에는 레퍼런스 번호와 질감·크롭·레이어 등 비교할 특징을 적는다. 필요한 글꼴과 자산 범위를 콘텐츠 에디터와 확인한다. [비주얼·모션 제작 가이드](../visual-production.md)
2. **실제 콘텐츠와 에셋을 넣어 시안을 만든다.** 신규·전면 디자인에서는 데스크톱·모바일 첫 화면과 대표 상세를, 일부 수정에서는 요청한 요소와 영향받는 화면을 만든다. 긴 제목과 이미지 크롭, 읽는 순서와 버튼 접근성을 확인한다. CSS로 표현하기 어려운 사진 효과나 질감은 독립 이미지로 제작하거나 내보내고, 필요하면 승인된 자료로 이미지 생성 도구를 사용한다. 개발자에게 파일과 해상도, 비율, 투명도, 배치 순서·크롭을 넘기고 실제 브라우저에서 본 차이를 회신받는다.
3. **구현에 필요한 디자인 값을 기록한다.** 배경·본문·강조·테두리 등 색상 역할, 글자 크기와 줄 높이, 간격, 최대 폭과 반응형 전환 기준을 정리한다. 카드, 버튼, 내비게이션, 갤러리 등 실제 사용하는 컴포넌트에 내부 배치와 기본·호버·키보드 포커스·선택 상태를 명시한다. 사용되는 경우 이미지 없음과 긴 콘텐츠의 상태도 포함한다.
4. **모션 결정을 준비한다.** 전환이 탐색이나 콘텐츠 이해를 돕는 위치를 고른다. 개발자와 실제 크기의 화면에서 스크롤 연동, 순차 등장이나 카드 전환에 맞는 모션 라이브러리를 시험한다. 트리거, 움직이는 대상, 시작·끝 상태, 대략적인 시간, 모바일과 축소 모션을 짧은 영상이나 실행 예제로 보여준다. 효과가 승인되면 이징, 반대 방향, 빠른 연속 입력과 종료 상태를 명세에 기록한다.
5. **시안 피드백을 받고 적용한다.** PM에게 사용자에게 보여줄 화면 파일이나 미리보기, 대표 화면에서 검토할 결정, 필요한 모션 선택을 함께 전달한다. 피드백을 받으면 영향을 받는 화면과 컴포넌트를 수정하고, 수정 전후에서 달라진 부분을 표시한 최신 시안을 다시 전달한다. 사용자 승인 버전으로 개발자 인계를 준비한다.
6. **구현을 설계와 대조한다.** 프런트엔드 개발자와 브라우저에서 실제 콘텐츠의 줄바꿈, 좌우 정렬, 컴포넌트 상태, 모션 종료 화면을 확인한다. 차이가 있으면 화면 크기, 위치, 기대 상태를 구체적으로 적어 수정 요청을 전달한다. 구현 제약으로 시안을 바꿀 때는 대안을 화면으로 보여주고 사용자 선택이 필요한 부분을 PM에게 올린다.

## 산출물과 완료 기준

- **시안**에는 실제 콘텐츠가 들어간 작업 범위의 데스크톱·모바일 화면이 있다. PM이 열어서 사용자에게 보여줄 수 있다.
- **디자인 명세와 에셋**에는 승인 시안 버전, 컬러·타이포그래피·간격, 컴포넌트와 상태, 반응형 배치 규칙, 사용할 이미지 파일과 크롭 기준이 있다.
- **모션 명세**에는 효과별 승인 상태와 개발에 필요한 값이 있다. 프런트엔드 개발자는 이미지와 규칙을 연결해 구현할 수 있고 QA/배포는 예상 동작을 재현할 수 있다.
