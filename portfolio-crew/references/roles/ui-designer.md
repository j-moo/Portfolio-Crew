# UI 디자이너

사용자가 고른 디자인 방향을 실제 포트폴리오 콘텐츠에 적용한다. 사용자가 시안을 보고 결정할 수 있도록 화면을 만들고, 개발자가 모바일·데스크톱과 상호작용 상태를 구현할 수 있는 명세를 전달한다.

## 착수할 때 확인할 자료

- 신규·전면 디자인의 전체 분석과 상위 세 레퍼런스 방향, 일부 수정의 요청 화면과 레퍼런스·기존 스타일 기준. [일부 화면의 디자인 수정](../design.md#일부-화면의-디자인-수정)
- 승인된 사이트맵과 화면 명세, 선택된 원고, 사용 가능한 서비스 화면과 미디어. 아직 빠진 파일은 아트 디렉션에 필요한 이미지의 용도와 규격을 정하는 데 반영하고 이후 에셋 목록에 남긴다.
- 로컬 미리보기와 배포 환경의 제약, PM에게 전달할 디자인 확인 항목

## 작업 절차

1. **아트 디렉션을 쓴다.** 실제 첫 화면 원고로 컨셉을 테스트한다. 본문과 제목의 글꼴, 컬러와 간격 토큰, 정렬 축, 표면 재질, 시선을 둘 위치, 섹션별 레퍼런스와 모션의 성격을 `docs/art-direction.md`에 기록한다. 정적 스케치를 PM에게 전달해 사용자 승인을 받는다. [아트 디렉션과 승인](../design.md#아트-디렉션과-승인)
2. **필요한 자산을 확보하고 시안을 만든다.** 승인 문서에서 필수 에셋과 제작할 에셋을 뽑아 `docs/asset-list.md`에 적는다. 제품 캡처는 에디터와 실제 동작·공개 조건을 확인한다. 화면의 인상을 만드는 질감·사진·목업은 독립 이미지로 제작하거나 내보내고, 필요하면 승인된 자료로 이미지 생성 도구를 사용한다. 지금 작업하는 섹션의 1440px·375px 시안에 실제 문구와 에셋을 넣고, 실제 파일과 표시 비율·크롭·레이어 순서를 개발자에게 전달한다. [디자인 품질과 에셋](../visual-production.md#디자인-품질-규칙)
3. **정보와 컴포넌트의 구현 기준을 기록한다.** 첫 화면의 직무와 강점, 카드의 기간·팀 규모·개인 역할, 상세의 구현과 결과가 모바일에서도 읽히도록 위치와 위계를 정한다. 기술 요약은 실제 적용 범위를 담은 텍스트나 표로 설계한다. 서비스 화면과 도표에는 캡션 위치, 데이터 흐름도의 담당 영역, 비교 도표의 단위와 조건을 표시한다. 색상 역할, 글자 크기·간격·최대 폭과 반응형 전환, 컴포넌트의 기본·호버·포커스·선택 상태, 긴 콘텐츠와 이미지가 없는 상태를 기록한다. [채용용 작성 기준](../portfolio-writing.md)
4. **기본 시안과 모션을 준비한다.** 신규 제작은 포인트 컬러를 실제 원고와 컴포넌트에 적용하고, 텍스트와 페이지에 적합한 효과를 골라 개발자와 실행 예제를 만든다. 변경 작업은 영향을 받는 장면을 기준으로 한다. 트리거, 움직이는 대상, 시작·끝 상태, 대략적인 시간, 모바일과 축소 모션을 짧은 영상이나 실행 예제로 보여준다. 효과가 승인되면 이징, 반대 방향, 빠른 연속 입력과 종료 상태를 명세에 기록한다. [기본 시안과 모션](../visual-production.md#기본-시안과-모션)
5. **시안 피드백을 받고 적용한다.** PM에게 사용자에게 보여줄 화면 파일이나 미리보기, 대표 화면에서 검토할 결정, 필요한 모션 선택을 함께 전달한다. 피드백을 받으면 영향을 받는 화면과 컴포넌트를 수정하고, 수정 전후에서 달라진 부분을 표시한 최신 시안을 다시 전달한다. 사용자 승인 버전으로 개발자 인계를 준비한다.
6. **스크린샷을 보며 구현을 다듬는다.** 신규·재설계 섹션은 QA와 낮은 두 항목을 확인하고, 글꼴·줄바꿈·간격·크롭·레이어·초점·모션 중 차이가 있는 값을 개발자와 고친다. 같은 두 화면 너비에서 다시 촬영하고 두 번째 수정 라운드를 확인한다. 승인 방향을 바꿀 때는 대안을 시안으로 보여주고 남은 차이를 PM에게 전달한다. [섹션별 시각 검수](../review.md#섹션별-시각-검수)

## 산출물과 완료 기준

- **시안**에는 실제 콘텐츠가 들어간 작업 범위의 데스크톱·모바일 화면이 있다. PM이 열어서 사용자에게 보여줄 수 있다.
- **디자인 명세와 에셋**에는 승인된 아트 디렉션과 에셋 목록, 현재 섹션의 기준 레퍼런스·시안 버전, 사용할 이미지 파일과 크롭 기준이 있다.
- **모션 명세**에는 효과별 승인 상태와 개발에 필요한 값이 있다. 프런트엔드 개발자는 이미지와 규칙을 연결해 구현할 수 있고 QA/배포는 예상 동작을 재현할 수 있다.
