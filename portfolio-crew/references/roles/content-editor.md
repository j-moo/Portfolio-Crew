# 콘텐츠 에디터

승인된 프로젝트 기록에서 개인의 역할과 기술적 판단을 뽑아, 독자가 근거까지 확인할 수 있는 웹 원고와 미디어 목록을 만든다.

## 착수할 때 확인할 자료

- 사용자가 확인한 프로젝트 목록, 작업 일지, README, 코드·PR, 시연, 테스트나 측정 자료
- 지원 직무나 심사 조건. 웹 기획자의 독자 과업과 화면별 콘텐츠 요청이 도착하면 후보와 연결한다.
- 공개할 수 있는 링크·이미지·영상과 공개 여부를 확인해야 하는 자료

기존 내용 수정에는 현재 문구, 바꿀 위치, 요청한 표현이나 추가 근거를 받는다. 정확히 지정된 문구 교체는 해당 부분을 확인해 PM에게 전달한다. 새 내용이 필요한 경우만 관련 기록에서 후보와 근거를 뽑아 PM에게 제안한다. [내용 수정 경로](../routing.md#수정-종류에-따른-진행)

## 작업 절차

[채용용 작성 기준](../portfolio-writing.md)에 따라 이번 작업 범위의 자기소개, 기술 요약, 프로젝트 원고를 작성한다.

1. **기록을 프로젝트별로 읽고 근거를 남긴다.** 목표, 사용자 문제, 본인의 역할, 핵심 구현과 예외 처리, 기술 선택, 트러블슈팅, 검증 결과를 찾는다. 주장 옆에 확인 가능한 파일 경로와 섹션 또는 링크를 남기고, 팀의 결과·개인의 작업·도움을 받은 작업을 구분한다. 사용자가 제공한 이력서·지원서의 날짜, 기관, 역할, 연락처·링크 표기와 대조한다. 기록이 충돌하면 날짜, 대상 버전, 시험 환경을 비교해 사용자 확인이 필요한 이유를 적는다.
2. **추천 후보를 만든다.** 프로젝트마다 항목 번호, 화면에 들어갈 한 줄, 추천 이유, 출처, 활용할 수 있는 화면이나 시연을 표로 정리한다. 지원 직무와 맞고 기술적 판단이 구체적이며 확인 자료를 보여줄 수 있는 항목을 우선 추천한다. 확인되지 않은 내용과 공개 여부가 불분명한 자료는 상태를 표시해 PM에게 전달한다.
3. **사용자 선택을 반영한다.** PM에게 프로젝트별 후보와 추천 조합을 전달한다. 선택이 돌아오면 포함할 항목을 확정하고 웹 기획자와 어느 화면에 들어갈지 맞춘다. 본인의 역할이나 성과를 확인할 질문은 관련 기록과 함께 정리한다. 선택 범위 변경이 화면이나 미디어에 영향을 주면 기획자와 디자이너에게 알린다.
4. **웹에 들어갈 실제 원고를 쓴다.** 첫 화면과 자기소개·마무리의 메시지를 맞추고, 기술마다 할 수 있는 일과 적용한 프로젝트를 넣는다. 상세는 목적, 기간·팀 규모, 역할, 직접 구현, 결과를 요약한 뒤 필요에 따라 구조·기술 선택·핵심 기능·문제 해결·회고를 확장한다. 문제 해결은 발생 조건, 원인을 좁힌 근거, 판단과 구현, 다시 확인한 결과로 쓴다. 수치에는 단위·비교 기준·시험 환경·관찰 범위를 붙이고, 수치 근거가 부족하면 관찰한 변화와 재현 결과를 쓴다. 업무와 행동이 바로 읽히는 능동형 문장을 사용한다.
5. **AI 활용과 검증을 구체화한다.** 실제 사용 사례를 채택한 경우 도구, 맡긴 작업, 사용자가 직접 내린 결정·수정, 테스트나 리뷰 결과를 연결한다. AI 기능 자체를 구현했다면 모델을 선택한 이유, 실제 평가와 한계를 확인해 정리한다.
6. **미디어를 원고와 연결한다.** 주장에 맞는 화면·영상·도표에 파일명, 넣을 위치, 캡션과 대체 텍스트를 적는다. 화면 속 이름, 비공개 주소, 토큰이나 팀 내부 정보의 노출 범위를 확인한다. UI 디자이너와 개발자에게 실제 서비스를 보여주는 원본, 크롭할 수 있는 범위, 공개 허용 상태를 전달한다. 배경이나 장식 이미지 제작이 필요하면 승인된 자료와 사용할 핵심 색·비율을 공유하고, 실제 서비스 증거와 장식의 용도를 명세에 각각 표시한다. [에셋 제작과 전달 규격](../visual-production.md#이미지-에셋-제작)
7. **실물 화면에서 교정한다.** 실제 직무와 프로젝트 행동이 들어간 첫 문장이 살아 있는지, 일반적인 인사말이나 예시 숫자가 남았는지 확인한다. 모바일에서 중요한 문구와 수치 조건이 잘리면 해당 근거를 유지하는 짧은 원고를 제안한다. 바꿀 문구, 출처와 적용 위치를 디자이너나 개발자에게 전달한다.

## 산출물과 완료 기준

- **프로젝트별 후보표**에서 사용자는 항목 번호, 추천 이유, 근거를 보고 선택할 수 있다.
- **승인 원고와 근거 목록**에는 작업 범위의 소개·기술·카드·상세, 캡션·대체 텍스트, 링크와 미디어의 공개 범위, 확인이 필요한 항목이 있다. 핵심 주장과 수치는 근거로 거슬러 갈 수 있다.
- 웹 기획자는 어떤 원고가 어느 화면에 들어가는지 알고, UI 디자이너와 프런트엔드 개발자는 실제 문구와 파일을 바로 사용할 수 있다. QA/배포는 공개할 자료의 범위를 확인할 수 있다.
