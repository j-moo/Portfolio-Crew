# 변경 범위와 브라우저 검수

## 부분 수정의 기준 버전

1. 사용자 지정 커밋, 릴리스 또는 사이트 상태를 확인한다. 원격 버전이 기준이라면 그 버전이 어느 커밋과 배포를 가리키는지 확인한다. 기준과 현재 상태를 함께 실행할 때는 각 버전이 자기 에셋을 쓰도록 분리한다.
2. 허용 변경과 보존 대상을 화면 단위로 적는다. 예를 들어 ‘상세 설명과 AI 탭’이 범위라면 기존 홈, 프로젝트 진입, 상세의 갤러리·시연·도표·개발 기록, 이전 화면으로 돌아가기를 검수한다. 한 HTML 파일에 여러 기능이 있다면 파일 검사에 더해 DOM이나 사용자 동작을 비교한다.
3. 기준과 변경본을 같은 뷰포트·경로·상태로 확인한다. 화면 차이가 발견되면 레이아웃, 콘텐츠, 에셋, 실행 상태 중 무엇이 달라졌는지 확인한다. 원고 변경처럼 기대한 차이를 기록해 비교 근거를 남긴다.

```sh
node /path/to/portfolio-crew/scripts/check-scope.mjs --repo . --base HEAD --allow src/project-detail.html --allow src/ai/
```

`--base`에 검수 기준 커밋이나 ref를 넣는다. `--allow`는 저장소 루트 상대 경로이며 여러 번 지정할 수 있다. 디렉터리 전체를 허용할 때는 슬래시로 끝낸다. 검사에는 기준 커밋 대비 작업 트리, 스테이징 영역, Git이 무시하지 않는 미추적 파일이 포함된다.

## 실제 브라우저 검수

- 대표 진입점에서 상세를 열고, 미디어 확대나 재생, 접힌 기록, 외부 근거 링크, 사이드바와 뒤로가기를 확인한다. 이미지 로드와 영상 재생을 직접 확인한다. 긴 실제 제목, 좁은 모바일, 키보드 조작도 확인한다.
- 모션은 실제 휠·터치·버튼으로 진입하고 빠르게 되돌린다. 첫 렌더링 이후 전환 시작 시점, 클릭과 스크롤의 도착 상태, 고정되는 영역, 중복 전환, 축소 모션에서의 가독성을 확인한다. 해당한다면 내부 스크롤 방향과 바깥 페이지 스크롤을 구분한다.
- 디자인·모션 변경은 데스크톱·모바일 캡처와 핵심 전환 녹화로 판단한다. 글이나 화면 위치를 검증하는 자동 검사와 함께 녹화를 재생해 체감 속도, 깜빡임, 끊김을 확인한다. 확인한 해상도, 브라우저, 축소 모션 설정을 기록한다.

기존 프로젝트에 브라우저 테스트가 있으면 활용한다. 가벼운 사용자 흐름 검사는 [예제 설정](../examples/browser-check.json)을 복사해 대상 사이트의 경로와 선택자로 바꿔 실행한다. 설치된 스킬 폴더에 쓸 수 없으면 스킬 폴더를 쓰기 가능한 임시 경로에 복사해 그 경로에서 의존성을 설치한다.

```sh
npm --prefix /path/to/portfolio-crew ci
npm --prefix /path/to/portfolio-crew exec -- playwright install chromium
node /path/to/portfolio-crew/scripts/check-portfolio.mjs --url http://localhost:4173/ --baseline http://localhost:4174/ --config ./browser-check.json --output ./.portfolio-qa
```

`--baseline`은 선택 사항이다. 함께 실행하면 공통 흐름을 두 버전에서 검사하고 `currentOnly`로 표시한 새 경로는 변경본에서 검사한다. 실행 폴더 아래 대상·화면·흐름별 스크린샷이 생성된다. `--record`를 추가하면 Playwright 동영상도 저장한다. 배포 후에는 공개 주소를 새 브라우저 세션에서 열어 제출 링크와 파일 다운로드를 확인한다.

이미 설치된 Chrome을 사용하려면 Chromium 설치를 생략하고 검사 명령에 `--channel chrome`을 추가한다. 이 환경에서 녹화하려면 `npm --prefix /path/to/portfolio-crew exec -- playwright install ffmpeg`로 녹화에 필요한 도구를 설치한다.

### 브라우저 검사 설정

각 흐름은 고유한 영문 소문자 이름 `name`, 시작 경로 `path`, 순서대로 실행할 `steps`를 받는다. 경로는 각각의 실행 URL을 기준으로 해석된다. GitHub Pages가 하위 경로에서 실행되면 끝에 슬래시가 붙은 URL과 `./`로 시작하는 경로를 사용한다. 선택자는 각 상태에서 요소 한 개를 가리키도록 작성한다.

| `action` | 설정과 동작 |
| --- | --- |
| `click` | `selector`에 지정한 요소를 클릭한다. 모바일에서는 탭한다. |
| `visible` | `selector`에 지정한 요소가 화면에 표시될 때까지 기다린다. |
| `text` | `selector`에 지정한 요소에 기대하는 `text`가 포함되고 표시되는지 확인한다. |
| `url` | 경로와 해시를 포함한 주소가 `path`와 일치할 때까지 기다린다. |
| `press` | `key`를 누른다. `selector`가 있으면 해당 요소에 포커스를 둔다. |
| `wheel` | `deltaY`만큼 휠 입력을 보낸다. `selector`가 있으면 그 요소 위에서 실행한다. |
| `back` | 브라우저 방문 기록에서 한 단계 돌아간다. |

검사는 데스크톱, 터치 모바일, 축소 모션 프로필을 실행한다. 검사 실패는 종료 코드 1로, 설정이나 실행 오류는 종료 코드 2로 표시한다.
