# 변경 범위와 브라우저 검수

내장 검사 스크립트를 실행할 때 Node.js 20 이상을 사용한다. 프로젝트의 기존 테스트나 이용 가능한 브라우저 도구로도 검수할 수 있다.

## 부분 수정의 기준 버전

1. 사용자 지정 커밋, 릴리스 또는 사이트 상태를 확인한다. 원격 버전이 기준이라면 그 버전이 어느 커밋과 배포를 가리키는지 확인한다. 기준과 현재 상태를 함께 실행할 때는 각 버전이 자기 에셋을 쓰도록 분리한다.
2. 허용 변경과 보존 대상을 화면 단위로 적는다. 예를 들어 ‘상세 설명과 AI 탭’이 범위라면 기존 홈, 프로젝트 진입, 상세의 갤러리·시연·도표·개발 기록, 이전 화면으로 돌아가기를 검수한다. 한 HTML 파일에 여러 기능이 있다면 파일 검사에 더해 DOM이나 사용자 동작을 비교한다.
3. 기준과 변경본을 같은 뷰포트·경로·상태로 확인한다. 화면 차이가 발견되면 레이아웃, 콘텐츠, 에셋, 실행 상태 중 무엇이 달라졌는지 확인한다. 원고 변경처럼 기대한 차이를 기록해 비교 근거를 남긴다.

```sh
node /path/to/portfolio-crew/scripts/check-scope.mjs --repo . --base HEAD --allow src/project-detail.html --allow src/ai/
```

`--base`에 검수 기준 커밋이나 ref를 넣는다. `--allow`는 저장소 루트 상대 경로이며 여러 번 지정할 수 있다. 디렉터리 전체를 허용할 때는 슬래시로 끝낸다. 검사에는 기준 커밋 대비 작업 트리, 스테이징 영역, Git이 무시하지 않는 미추적 파일이 포함된다.

같은 저장소에 진행 메모가 있다면 로컬 범위 검사에서만 메모 경로를 허용할 수 있다. 게시 폴더와 공개 커밋 후보에서는 메모를 별도로 제외하고, 검사 전에 이미 있던 사용자 변경은 이번 수정과 구분해 확인한다.

## 채용 내용 검수

신규는 최종 원고와 실제 화면을 함께 검수한다. 기존 사이트는 수정한 내용과 이에 의존하는 화면에 아래 항목을 적용한다. [채용용 작성 기준](portfolio-writing.md)

- 첫 화면에서 지원 직무와 강점을 읽을 수 있고, 기술 요약에서 구체적인 활용 범위를 확인한 뒤 대표 상세로 이동할 수 있는지 본다. 처음 제시한 강점이 소개·프로젝트·마무리에서 일관되게 확인되는지 비교한다.
- 카드의 기간·팀 규모·역할과 프로젝트 상세의 해당 정보를 대조한다. 직접 구현한 기능과 팀 성과가 구분되고, 문제의 발생 조건·원인·해결·검증을 화면, 로그, 코드나 실험 등 연결된 근거에서 확인할 수 있는지 점검한다. 수치의 단위와 비교 조건이 일치하는지, AI 사례에 사용 범위와 직접 수행한 검증이 있는지 확인한다.
- 휴대폰 화면에서도 캡션과 표가 읽히고 서비스 화면·개발 기록·시연의 링크가 실제로 열리는지 확인한다. 양식의 샘플 문구·수치·연락처·작성 안내는 최종 사이트에서 찾아 정리한다.
- 사진, 연락처와 사용한 자산의 공개 범위를 승인과 대조한다. 이미지 속 비공개 정보와 HTML·다운로드에 포함된 파일도 함께 확인한다. 공개용 링크는 로그아웃 상태로 열고, 비공개 자료는 승인된 설명과 접근 범위를 확인한다.

## 섹션별 시각 검수

신규 제작과 디자인이 바뀐 섹션에 적용한다. 첫 캡처를 기준으로 삼아 **비교·채점 → 약한 두 항목 수정 → 재촬영과 확인**을 최소 두 라운드 실행한다. QA는 각 라운드의 전후 캡처와 바뀐 항목을 기록한다.

1. 실제 브라우저에서 글꼴과 이미지가 로드되고 기본 모션이 끝난 상태를 **1440px와 375px** 너비로 캡처한다. 화면 경로·뷰포트·스크롤 위치·UI 상태를 기록하고, 같은 조건으로 재촬영한다. 동작 자체는 필요할 때 짧게 녹화한다.
2. 각 크기의 **원본 레퍼런스 → 승인 이미지 → 브라우저 캡처**를 같은 장면으로 맞춰 나란히 본다. 레퍼런스가 시안에 어떻게 반영됐는지, 승인 이미지에서 구현으로 넘어갈 때 어디가 달라졌는지 기록한다. 모바일 레퍼런스가 없으면 승인한 모바일 시안과 데스크톱 레퍼런스의 시각적 원리를 기준으로 판단한다. 글꼴은 브라우저가 실제로 사용한 서체·굵기와 줄바꿈을, 색은 시안의 값과 화면에서 계산된 값을 확인한다. 대표 이미지는 에셋 파일 로딩, 크롭과 질감까지 확인한다.
3. 아래 항목을 크기별로 1~5점으로 평가한다. 1점은 핵심 장면이나 동작의 누락, 3점은 눈에 띄는 차이, 5점은 의도한 모습과 동작을 확인한 경우다. 점수에 근거가 되는 영역이나 상태를 함께 적는다. 낮은 점수의 항목 두 개를 UI 디자이너와 개발자에게 전달해 먼저 수정한다.
4. 같은 장면을 찍어 수정 근거와 줄바꿈·에셋·초점의 회귀를 확인한다. 이 결과로 다시 채점해 두 번째 수정과 재촬영을 진행한다. PM에게 최종 캡처, 점수의 변화, 고친 항목, 남은 차이와 화면에 미치는 영향을 전달한다.

| 채점 항목 | 캡처와 동작에서 확인할 내용 |
| --- | --- |
| 컨셉과 읽는 순서 | 제목·대표 이미지·여백에서 합의한 컨셉이 읽히고, 섹션의 핵심이 먼저 보인다. |
| 타이포그래피 | 표시 글꼴, 제목과 본문의 크기 대비, 줄바꿈과 행간이 실제 문구에 맞는다. |
| 구도와 통일감 | 섹션의 목적에 맞는 정렬·그리드·이미지 크기를 사용하고, 공통 토큰으로 앞뒤 화면과 연결된다. |
| 기본값과 조작 상태 | [피할 기본값](visual-production.md#피할-기본값)을 확인하고 링크·버튼의 호버·포커스와 선택 상태를 검수한다. |
| 에셋·질감·여백과 모션 | 승인 시안과 레퍼런스의 시각적 원리대로 크롭·레이어·표면·간격을 구현했으며, 실제 입력에서 의도한 모션이 보인다. |

필수 에셋이 준비되지 않았거나 실제 화면을 캡처할 수 없으면 현재 상태와 빠진 검수를 기록하고 섹션 완료를 보류한다. 최종 QA는 승인된 모든 섹션을 연결해 직접 주소, 모바일과 키보드 이동, 에셋·모션의 로딩 상태를 다시 확인한다.

신규·재설계의 조립 결과는 승인 와이어프레임의 섹션 순서와 목적, 재사용 컴포넌트의 짧고 긴 상태, `docs/tokens.md`와 승인 에셋을 대조한다. 테스트 문구와 부품을 임시로 넣은 페이지는 검수 대상으로 관리한다. [컴포넌트 검수와 조립](component-production.md)

## 실제 브라우저 검수

- 대표 진입점에서 상세를 열고, 미디어 확대나 재생, 접힌 기록, 외부 근거 링크, 사이드바와 뒤로가기를 확인한다. 이미지 로드와 영상 재생을 직접 확인한다. 긴 실제 제목, 좁은 모바일, 키보드 조작도 확인한다.
- 모션은 실제 휠·터치·버튼으로 진입하고 빠르게 되돌린다. 첫 렌더링 이후 전환 시작 시점, 클릭과 스크롤의 도착 상태, 고정되는 영역, 중복 전환, 축소 모션에서의 가독성을 확인한다. 해당한다면 내부 스크롤 방향과 바깥 페이지 스크롤을 구분한다.
- 제목이나 숫자에 모션이 있으면 동작 중, 종료 후, 축소 모션 상태에서도 완성된 문구와 실제 수치에 접근할 수 있는지 확인한다. 카드나 버튼 움직임에는 터치·키보드 동작과 포커스를, 포인트 컬러 변경에는 실제 배경과 링크·선택 상태의 가독성을 확인한다. [비주얼·모션 적용 기준](visual-production.md#모션-후보와-적용-조건)
- 디자인·모션 변경은 데스크톱·모바일 캡처와 핵심 전환 녹화로 판단한다. 글이나 화면 위치를 검증하는 자동 검사와 함께 녹화를 재생해 체감 속도, 깜빡임, 끊김을 확인한다. 확인한 해상도, 브라우저, 축소 모션 설정을 기록한다.
- 이미지 에셋이 인상을 결정하는 장면은 승인 시안과 같은 화면 폭에서 크롭과 질감을 비교한다. CDN에 의존하는 모션은 테스트 환경에서 요청을 차단해 콘텐츠와 이동이 가능한지 별도로 확인한다. 브라우저 도구나 프로젝트 테스트를 사용해 실패 조건과 화면을 남긴다. [비주얼·모션 제작 가이드](visual-production.md)

기존 프로젝트에 브라우저 테스트가 있으면 활용한다. 가벼운 사용자 흐름 검사는 [예제 설정](../examples/browser-check.json)을 복사해 대상 사이트의 경로와 선택자로 바꿔 실행한다. 설치된 스킬 폴더에 쓸 수 없으면 스킬 폴더를 쓰기 가능한 임시 경로에 복사해 그 경로에서 의존성을 설치한다.

```sh
npm --prefix /path/to/portfolio-crew ci
npm --prefix /path/to/portfolio-crew exec -- playwright install chromium
node /path/to/portfolio-crew/scripts/check-portfolio.mjs --url http://localhost:4173/ --baseline http://localhost:4174/ --config ./browser-check.json --output ./.portfolio-qa
```

`--baseline`은 선택 사항이다. 함께 실행하면 공통 흐름을 두 버전에서 검사하고 `currentOnly`로 표시한 새 경로는 변경본에서 검사한다. 실행 폴더 아래 대상·화면·흐름별 스크린샷이 생성된다. `--record`를 추가하면 Playwright 동영상도 저장한다. 배포 후에는 공개 주소를 새 브라우저 세션에서 열어 제출 링크와 파일 다운로드를 확인한다.

이미 설치된 Chrome을 사용하려면 Chromium 설치를 생략하고 검사 명령에 `--channel chrome`을 추가한다. 이 환경에서 녹화하려면 `npm --prefix /path/to/portfolio-crew exec -- playwright install ffmpeg`로 녹화에 필요한 도구를 설치한다.

### 브라우저 검사 설정

각 흐름은 고유한 영문 소문자 이름 `name`, 시작 경로 `path`, 순서대로 실행할 `steps`를 받는다. 경로는 각각의 실행 URL을 기준으로 해석된다. GitHub Pages가 하위 경로에서 실행되면 끝에 슬래시가 붙은 URL과 `./`로 시작하는 경로를 사용한다. 선택자는 각 상태에서 요소 한 개를 가리키도록 작성한다.

| `action` | 설정과 동작 |
| --- | --- |
| `click` | `selector`에 지정한 요소를 클릭한다. 모바일에서는 탭한다. |
| `visible` | `selector`에 지정한 요소가 화면에 표시될 때까지 기다린다. |
| `text` | `selector`에 지정한 요소에 기대하는 `text`가 포함되고 표시되는지 확인한다. |
| `url` | 경로와 해시를 포함한 주소가 `path`와 일치할 때까지 기다린다. |
| `press` | `key`를 누른다. `selector`가 있으면 해당 요소에 포커스를 둔다. |
| `wheel` | `deltaY`만큼 휠 입력을 보낸다. `selector`가 있으면 그 요소 위에서 실행한다. |
| `back` | 브라우저 방문 기록에서 한 단계 돌아간다. |

검사는 데스크톱, 터치 모바일, 축소 모션 프로필을 실행한다. 검사 실패는 종료 코드 1로, 설정이나 실행 오류는 종료 코드 2로 표시한다.
