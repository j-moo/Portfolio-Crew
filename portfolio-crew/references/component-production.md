# 토큰과 재사용 컴포넌트

신규 제작과 시각 재설계에서는 승인된 아트 디렉션의 단일 레퍼런스로 색·서체·배경·컴포넌트의 규칙을 맞춘다. 사용자가 제공하거나 승인한 와이어프레임의 섹션 순서와 목적을 적용한다. 기존 사이트의 일부 수정은 해당 화면과 기존 컴포넌트·토큰을 기준으로 한다.

## 토큰과 컴포넌트 목록

1. **공통 값을 기록한다.** 작업 프로젝트의 `docs/tokens.md`에 CSS 변수 이름, 값, 쓰임과 확인한 레퍼런스 부분을 적는다. 필요한 색·틴트·투명도, 테두리, 블러, 반경, 그림자, 글꼴·굵기·자간·행간, 간격·컴포넌트 상태를 다룬다. 이미지에서 확인한 값과 시안에서 조정한 값을 구분한다. 스크린샷의 결과만으로 정확히 알아낼 수 없는 블러·투명도·폰트는 비교를 거쳐 승인한 값으로 기록한다.
2. **페이지에 필요한 부품을 확인한다.** 와이어프레임의 각 섹션에 사용할 컴포넌트, 필요한 콘텐츠 슬롯과 길이 범위, 기본·호버·포커스·선택 상태를 적는다. 카드·배지·버튼 등의 형태와 간격은 최종 레퍼런스와 승인 시안에서 가져온다. 그대로 재현할 권한이 확인된 화면은 그 범위 내에서 재현한다. 나머지 화면은 관찰한 원리를 사용자의 콘텐츠와 구도에 맞게 적용한다.
3. **토큰과 부품을 시안 승인에 포함한다.** 실제 글꼴과 팔레트, 컴포넌트가 보이는 시안과 아트 디렉션에서 토큰과 필요한 부품을 확정한다. 조립 중 새로 필요한 부품은 적용 위치와 용도를 목록에 남기고 보고한다. 눈에 보이는 스타일이나 부품이 달라지면 바뀐 시안을 보여주고 현재 결정 하나를 확인한다.

## 제작과 컴포넌트 검수

1. **콘텐츠를 교체할 수 있게 구현한다.** 아트 디렉션과 해당 시안을 승인받은 뒤, HTML·CSS 컴포넌트를 `components/` 또는 기존 컴포넌트 폴더에 만든다. 제목·배지·기간·태그·수치·버튼 등 실제 필요한 내용을 이름 있는 자리로 설계한다. Flexbox·Grid, 내용에 따라 늘어나는 높이, 필요한 곳에 `clamp()`·줄바꿈을 사용한다. 글꼴·색·간격·테두리는 승인 토큰을 참조한다.
2. **짧은 상태와 긴 상태를 한 화면에서 시험한다.** 같은 컴포넌트를 두 번 렌더링해 짧고 긴 실제 콘텐츠 또는 비공개 검수용 자리표시자를 배치한다. 데스크톱에서는 나란히, 375px에서는 세로로 보며 제목 줄바꿈과 슬롯 확장, 조작 영역을 확인한다. 해당되면 선택 슬롯이 비어 있는 경우도 시험한다.
3. **스크린샷으로 두 번 비교하고 수정한다.** 비교할 배경과 상태를 맞춘 뒤 최종 레퍼런스의 장면, 승인 시안, 테스트 캡처를 나란히 놓는다. 블러·틴트·테두리·그림자·글자와 여백에서 어긋난 부분을 고치고 같은 조건으로 재촬영한다. 시각 검수 기록에 두 라운드의 차이와 수정을 남긴다.
4. **CSS에서 남은 시각 차이는 ImageGen 에셋으로 해결한다.** 재질·조명·반사·프레임처럼 CSS로 목표에 도달하지 못한 레이어는 최종 레퍼런스 및 승인 시안에 근거해 별도 래스터 에셋으로 만든다. 글자나 버튼이 없는 레이어와 필요한 투명 영역을 확보한다. 가변 콘텐츠·링크·버튼·포커스는 실제 HTML로 제공한다. 교체 뒤에는 같은 테스트와 캡처로 차이와 반응형 동작을 다시 확인한다. 승인받은 모습과 달라지는 변경은 이미지 시안으로 다시 확인받는다. [이미지 에셋 제작](visual-production.md#이미지-에셋-제작)

## 페이지 조립

승인·검수된 컴포넌트, 공통 토큰과 배경 에셋을 사용해 승인 와이어프레임을 조립한다. 사용자가 전달한 실제 문구·기간·기술·성과를 슬롯에 넣고, 섹션 간격과 배경 전환을 승인 토큰과 시안 범위에서 조정한다. 필요한 부품이 없으면 그 위치와 요구사항을 목록에 올리고 사용자 확인을 받은 뒤 제작으로 돌아간다.

QA는 1440px와 375px에서 섹션 순서와 목적, 컴포넌트 재사용 여부, 실제 로드된 폰트와 색이 토큰에 맞는지 확인한다. 새 배경과 래스터 레이어가 텍스트 가독성이나 조작 영역에 미치는 영향도 비교한다. [섹션별 시각 검수](review.md#섹션별-시각-검수)
