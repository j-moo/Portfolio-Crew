# 레퍼런스 분석과 디자인 결정

## 모든 레퍼런스 분석

사용자가 확인한 목록의 각 레퍼런스를 직접 열어 분석한다. 글자나 세부 상태가 작으면 확대해서 확인한다. 작업 공간의 `reference-analysis.md` 또는 기존 문서 관례에 맞는 파일에 각 레퍼런스의 번호, 경로, 관찰 근거를 기록한다.

| 항목 | 레퍼런스마다 확인할 내용 |
| --- | --- |
| 스타일과 인상 | 시각적 위계, 화면의 핵심 장면, 정보 밀도, 질감, 사진·일러스트의 역할 |
| 색과 대비 | 배경·표면·텍스트·강조색의 역할, 주요 색상값을 확인할 수 있는 근거, 명암과 가독성 |
| 타이포그래피 | 제목·본문·레이블의 계층, 글꼴 계열과 굵기, 자간·행간, 줄바꿈, 한글과 영문 적용에 필요한 조건 |
| 구조와 간격 | 전체 그리드, 최대 폭, 정렬, 여백, 섹션 순서, 콘텐츠와 이미지의 비율, 화면 크기에 따른 변화 |
| 컴포넌트 | 헤더·사이드바·카드·버튼·탭·갤러리의 형태, 상태와 행동 단서, 테두리·그림자·모서리, 반복 규칙 |
| 인터랙션과 접근성 | 확인할 수 있는 전환, 탐색 방법, 키보드나 터치에 필요한 고려 사항, 콘텐츠가 길 때의 가독성 |
| 적용 판단 | 우리 포트폴리오의 어떤 화면에 어떤 특징을 사용할 수 있는지, 적용을 결정할 때 필요한 확인 |

관찰한 요소와 해석을 구분한다. 정지 이미지라면 움직임과 반응형 동작은 제안으로 기록하고, 폰트·정확한 수치를 확인할 수 없으면 관찰 가능한 범위와 추정 근거를 적는다.

## 동영상 레퍼런스 분석

재생할 수 있는 동영상은 레퍼런스 번호, 타임스탬프, 확인한 시작·종료 화면과 바뀌는 요소를 기록한다. 영상의 재생 속도와 실제 사이트에서 느껴질 움직임은 화면에서 확인한 근거에 맞춰 기록한다. 게시물 설명으로만 확인한 효과는 그 출처를 표시한다. 효과의 이름은 [모션 후보와 적용 조건](visual-production.md#모션-후보와-적용-조건)을 참고해 어떤 콘텐츠에 적용할지 제안하는 데 사용한다.

## 기본안과 상위 3개

신규 제작이나 사이트 전반의 디자인 방향을 정할 때 다음 흐름을 적용한다.

1. 여러 레퍼런스에서 반복되는 특징을 번호별 근거와 연결하고, 콘텐츠 읽기나 탐색에 적합한 특징을 기본 디자인과 UI로 정한다. 컬러 역할, 한글·영문 타이포그래피, 그리드와 간격, 첫 화면과 상세의 구조, 핵심 컴포넌트 규칙을 명시한다.
2. 전체 분석 결과 링크와 공통 요소 요약, 번호가 붙은 이미지 목록, 기본 디자인 방향을 사용자에게 보여준다. 이 시점에 **가장 마음에 드는 레퍼런스 3개**를 번호나 파일명으로 고르게 한다. 선택이 모호하거나 다른 수가 오면 현재 선택을 보여주고 세 개를 확정한다.
3. 고른 세 레퍼런스의 분석 기록으로 돌아가 각 레퍼런스에서 가져올 특징과 적용 위치를 정한다. 예를 들어 첫 번째의 타이포그래피를 첫 화면에, 두 번째의 카드 구성을 목록에, 세 번째의 이미지 배치를 상세에 적용한다. 특징이 충돌하면 사용자가 선택한 이유와 실제 콘텐츠·모바일 가독성을 기준으로 적용안을 정리한다.
4. 선택 결과를 UI 디자이너에게 넘긴다. 디자이너가 공통 요소와 상위 3개에서 가져올 특징을 아래 아트 디렉션과 섹션별 구도로 구체화한다.

레퍼런스의 시각적 원리와 구조를 사용자의 콘텐츠에 맞게 적용한다. 공개할 화면·이미지·영상은 공개 가능한 자산으로 준비한다.

## 아트 디렉션과 승인

UI 디자이너는 웹 기획자의 섹션 구조, 에디터의 실제 헤드라인과 대표 사례, 레퍼런스 분석을 사용해 작업 프로젝트의 `docs/art-direction.md`를 작성한다. 기존 사이트의 부분 재설계는 변경하는 섹션과 이어지는 기존 디자인에 초점을 맞춘다.

| 문서 항목 | 구현자가 결정할 수 있어야 하는 내용 |
| --- | --- |
| 컨셉 | 첫 화면의 제목·대표 이미지·여백이 함께 전달할 인상을 한 문장으로 쓴다. 실제 프로젝트의 어떤 특징이 그 인상을 뒷받침하는지 적는다. |
| 글꼴 | 실제 불러올 본문용과 제목용 웹폰트, 한글·영문 범위와 대체 글꼴, 크기·굵기·행간, 데스크톱·모바일에서의 헤드라인 줄바꿈을 정한다. |
| 컬러·형태·간격 | 배경·본문·표면·강조의 색상값과 역할, 모서리·테두리, 그리드 열과 정렬, 여백 기준을 적는다. 강조색을 사용할 구체적인 위치도 정한다. |
| 섹션 구도 | 섹션별 목적과 시선이 먼저 가는 요소, 기준 레퍼런스 번호 및 관찰한 장면, 이미지 비율·크롭과 375px에서의 배치 변화를 적는다. 레퍼런스에서 채택한 원리를 우리 문구와 자료에 대입한다. |
| 이미지와 모션 | 인상을 좌우할 실제 화면·사진·질감·목업과 쓰임을 정한다. 텍스트 등장과 페이지 모션의 성격, 효과를 사용할 위치, 읽기와 탐색을 돕는 이유, 줄여서 표현할 때의 상태를 적는다. |

PM은 이 문서와 비교할 레퍼런스 장면을 보여주고 **아트 디렉션 승인 하나만** 요청한다. 승인 전에는 문서, 스케치, 정적인 디자인 시안으로 검토한다. 제작 파일과 실행 가능한 HTML·CSS·JS 미리보기, 모션 프로토타입은 승인 후 작성한다. 상위 3개 선택은 아트 디렉션 승인과 별개의 결정이다.

섹션 착수 때 아트 디렉션에 기록된 레퍼런스와 적용 위치를 사용한다. 사용자가 해당 매핑을 승인했으면 그 결정을 재사용한다. 기준이 비어 있거나 바뀌면 해당 섹션의 레퍼런스부터 하나만 확인받는다. 실제 원고와 사용 가능한 에셋이 들어간 시안을 사용자에게 보여주고 이어서 모션을 확인한다. [섹션별 제작 절차](production.md#섹션별-제작) · [디자인 품질 규칙](visual-production.md#디자인-품질-규칙)

## 일부 화면의 디자인 수정

1. [레퍼런스 확인](intake.md#레퍼런스-목록-확인)부터 시작하고, 요청한 요소에 맞는 이미지·링크·기존 스타일을 기준으로 삼는다. 확인된 레퍼런스 수와 요청 범위에 맞춰 분석한다.
2. 기준 화면에서 바꿀 요소, 적용할 레퍼런스 특징, 재사용할 레이아웃·콘텐츠·컴포넌트를 아트 디렉션에 남기고 해당 변경을 승인받는다. 공통 스타일 변경이 다른 화면에 영향을 주면 영향을 받는 화면을 함께 고려한다.
3. 실제 콘텐츠가 들어간 수정 시안과 필요한 모바일 상태를 보여주고 확인받는다. 자료가 변경되면 해당 화면의 시안과 필요한 에셋·모션을 다시 검토한다. 구현 뒤 기준 화면과 바뀐 화면, 연결된 기존 동선을 비교한다. [변경 범위와 브라우저 검수](review.md)
