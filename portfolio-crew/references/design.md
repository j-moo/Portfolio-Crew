# 레퍼런스 분석과 디자인 결정

## 최종 레퍼런스 분석

사용자가 확정한 레퍼런스의 원본을 직접 열고 글자나 세부 상태를 확대해 분석한다. 작업 공간의 `reference-analysis.md` 또는 기존 디자인 문서에 원본 번호와 경로, 관찰 근거를 기록한다. 선택 전에는 후보를 열고 구분할 수 있는지 확인하며, 자세한 분석은 원본 한 개를 확정한 다음 진행한다.

| 항목 | 레퍼런스마다 확인할 내용 |
| --- | --- |
| 스타일과 인상 | 시각적 위계, 화면의 핵심 장면, 정보 밀도, 질감, 사진·일러스트의 역할 |
| 색과 대비 | 배경·표면·텍스트·강조색의 역할, 주요 색상값을 확인할 수 있는 근거, 명암과 가독성 |
| 타이포그래피 | 제목·본문·레이블의 계층, 글꼴 계열과 굵기, 자간·행간, 줄바꿈, 한글과 영문 적용에 필요한 조건 |
| 구조와 간격 | 전체 그리드, 최대 폭, 정렬, 여백, 섹션 순서, 콘텐츠와 이미지의 비율, 화면 크기에 따른 변화 |
| 컴포넌트 | 헤더·사이드바·카드·버튼·탭·갤러리의 형태, 상태와 행동 단서, 테두리·그림자·모서리, 반복 규칙 |
| 인터랙션과 접근성 | 확인할 수 있는 전환, 탐색 방법, 키보드나 터치에 필요한 고려 사항, 콘텐츠가 길 때의 가독성 |
| 적용 판단 | 우리 포트폴리오의 어떤 화면에 어떤 특징을 사용할 수 있는지, 적용을 결정할 때 필요한 확인 |

관찰한 요소와 해석을 구분한다. 정지 이미지라면 움직임과 반응형 동작은 제안으로 기록하고, 폰트·정확한 수치를 확인할 수 없으면 관찰 가능한 범위와 추정 근거를 적는다.

## 동영상 레퍼런스 분석

재생할 수 있는 동영상은 번호와 타임스탬프, 확인한 시작·종료 화면과 바뀌는 요소를 기록한다. 게시물 설명으로만 확인한 효과는 그 범위를 표시한다. 디자인 후보로 등록된 장면은 해당 타임스탬프의 이미지로 참가시킨다. 사용자가 모션을 요청해 준 자료는 동작만 확인하고 최종 디자인 기준의 색·타이포그래피·형태에 맞춰 적용한다.

## 레퍼런스 선택

1. **실제 후보를 담은 HTML을 준비한다.** 사용자가 확정한 목록 순서와 번호를 유지한다. 열어 확인한 로컬 이미지 목록을 JSON 배열로 작업 폴더에 저장한다. 각 항목의 필수 값은 `id`와 `path`이며 `name`은 선택이다. 웹·동영상 레퍼런스는 허용된 캡처 파일로 넣는다. 예를 들어 `[{"id":1,"path":"./reference-1.png"}]`처럼 기록한다.

   [HTML 준비 스크립트](../scripts/build-reference-tournament.mjs)를 실행해 실제 이미지를 담은 독립 파일을 만든다. 아래 경로는 작업 환경에 맞춘다.

   ```sh
   node /path/to/portfolio-crew/scripts/build-reference-tournament.mjs .portfolio-crew/reference-candidates.json .portfolio-crew/reference-tournament.html
   ```

2. **한 페이지에서 대진을 진행하게 한다.** 생성한 HTML을 열 수 있는 링크로 전달한다. 브라우저에서 이미지 또는 키보드 `1`·`2`를 선택하면 다음 대진이 바로 열린다. 사용자는 최종 화면의 번호나 결과를 한 번만 채팅으로 전달한다. 홀수 후보는 대진 시작 시 필요한 부전승을 적용한다. 브라우저 저장을 지원하면 같은 파일에서 진행을 복원한다.
3. **예외는 필요한 경우에만 처리한다.** 사용자가 이미 한 장을 정했으면 바로 분석한다. 후보가 한 장뿐이고 미정이면 그 원본을 사용할지만 묻는다. 자동 준비를 실행할 수 없으면 [기본 HTML](../assets/reference-tournament.html)을 제공해 사용자가 이미지 파일을 선택하게 한다. HTML을 열 수 없으면 번호가 붙은 실제 이미지 모음에서 최종 한 개를 고르게 한다.
4. **선택 결과를 원본과 연결한다.** 진행 메모에 HTML 경로, 후보 번호와 원본 경로를 남긴다. 미리 채운 HTML은 번호로 확인하고, 파일을 직접 고른 경우는 결과의 파일명으로 대조한다. 동명 파일이 있어 구분이 필요하면 그 파일의 경로만 확인한다. 확정한 원본을 상세 분석한다. 이전 채팅 대진에서 이어갈 때는 남아 있는 후보만 HTML에 넣는다.

HTML과 후보 목록은 로컬 작업 파일로 관리한다. 자동으로 준비한 HTML에는 이미지가 포함되므로 승인 범위 안에서만 공유한다.

**디자인 기준은 최종 레퍼런스 하나다.** 분석한 색과 명도, 제목·본문의 위계, 그리드와 여백, 카드·버튼·탭의 형태를 전체 화면에 일관되게 적용한다. 추가 장면은 같은 원본에서 확인한다. 기본·포커스 등 조작 상태는 동일한 토큰으로 설계하고, 필요한 부품은 제작 목록에 올린다. 사용자 프로젝트의 캡처·사진은 콘텐츠 자료로 배치한다.

## 시안 이미지 제작

1. **확정된 원본을 시각 입력으로 전달한다.** 선택한 원본 한 개를 열어 확인한다. 전송할 수 있는 최종 레퍼런스 이미지 또는 같은 원본의 장면 캡처를 [ImageGen 작업](visual-production.md#이미지-에셋-제작)의 디자인 입력으로 사용한다. 사용자 콘텐츠는 사용 범위가 허용된 자료를 필요한 자리에 넣거나 비율과 용도를 표시한다. 시안의 구도는 사용자의 프로젝트에 맞춰 구성한다.
2. **화면의 인상을 이미지로 결정한다.** 신규·전면 재설계에서는 첫 화면과 프로젝트 목록·대표 상세가 이어지는 데스크톱·모바일 이미지 시안을 만든다. 긴 페이지는 앞뒤가 이어지는 장면 이미지로 검토할 수 있다. 일부 재설계는 바꾸는 영역의 데스크톱·모바일 시안으로 범위를 잡는다. 모델에는 승인된 짧은 제목과 필요한 시각 정보만 전달한다. 글자가 틀리거나 폰트가 시안과 달라지면 정적 디자인 도구에서 실제 문구와 사용할 글꼴을 올려 교정한다. 서비스 캡처나 지표는 확보한 실제 자료를 허용 범위 안에서 배치하거나 들어갈 자리와 용도를 표시한다.
3. **결과를 원본과 나란히 본다.** 스타일이 흐트러졌는지 색온도, 밝기와 채도, 글자 폭·행간, 사진과 여백 비율, 표면 질감을 해당 원본과 비교한다. 글로 적은 방향과 다른 결과는 이미지 입력과 수정할 요소를 좁혀 다시 만든다. 모바일 시안은 데스크톱 승인 후보와 같은 팔레트·글꼴·이미지 언어를 사용하되 읽기 순서와 크롭을 정한다.
4. **승인할 파일을 보여준다.** 프리뷰 이미지를 작업 폴더의 `.portfolio-crew/design/`에 버전별로 보관하고 사용자에게 직접 보여준다. 적용한 레퍼런스 원본, 데스크톱·모바일 시안, 실제 사용할 글꼴과 팔레트를 함께 검토할 수 있게 한다. 디자인 문서에 같은 파일을 가리키고, 사용자 피드백이 오면 해당 시안 이미지를 수정해 최신 버전으로 확인받는다.

## 아트 디렉션과 승인

UI 디자이너는 웹 기획자의 섹션 구조, 에디터의 실제 헤드라인과 대표 사례, 확정된 레퍼런스를 입력으로 만든 시안 이미지로 작업 프로젝트의 `docs/art-direction.md`를 작성한다. 문서에 최종 레퍼런스 원본과 적용한 부분을 남긴다. 기존 사이트의 부분 재설계는 변경하는 섹션과 이어지는 기존 디자인에 초점을 맞춘다.

| 문서 항목 | 구현자가 결정할 수 있어야 하는 내용 |
| --- | --- |
| 컨셉 | 첫 화면의 제목·대표 이미지·여백이 함께 전달할 인상을 한 문장으로 쓴다. 실제 프로젝트의 어떤 특징이 그 인상을 뒷받침하는지 적는다. |
| 글꼴 | 시안의 같은 문장을 실제 웹폰트로 조판해 제목용과 본문용을 고른다. 한글·영문 범위, 대체 글꼴, 굵기·행간·자간, 화면별 줄바꿈을 기록한다. |
| 컬러·형태·간격 | 시안 이미지에서 사용할 배경·본문·표면·강조색을 채취해 값과 위치를 정한다. 섹션별 여백, 열 너비·정렬, 모서리와 테두리, 크롭 기준을 이미지에서 잡아 기록한다. |
| 섹션 구도 | 섹션별 목적과 시선의 초점, 최종 레퍼런스에서 적용한 장면, 이미지 비율·크롭과 375px에서의 배치 변화를 적는다. |
| UI 컴포넌트 | 최종 레퍼런스의 카드·버튼·내비게이션에서 필요한 구성과 상태를 확인한다. 승인한 컴포넌트와 토큰을 기록하고 필요한 부품은 제작 목록에 올린다. [토큰과 컴포넌트](component-production.md) |
| 이미지와 모션 | 인상을 좌우할 실제 화면·사진·질감·목업과 쓰임을 정한다. 텍스트 등장과 페이지 모션의 성격, 효과를 사용할 위치, 읽기와 탐색을 돕는 이유, 줄여서 표현할 때의 상태를 적는다. |

PM은 데스크톱·모바일 시안 이미지와 최종 원본을 실제로 보여주고 문서를 함께 첨부해 **현재 시안과 아트 디렉션의 승인 하나만** 요청한다. 승인한 시안의 파일과 버전을 기록한다. 제작 파일과 실행 가능한 HTML·CSS·JS 미리보기, 모션 프로토타입은 승인 후 작성한다.

섹션을 시작할 때 아트 디렉션에 기록된 한 개의 기준에서 적용할 장면과 컴포넌트를 확인한다. 실제 원고와 사용 가능한 에셋이 들어간 시안을 사용자에게 보여주고 이어서 모션을 확인한다. 사용자가 준 와이어프레임을 승인한 경우 섹션 순서와 목적대로 시안과 페이지를 구성한다. [섹션별 제작 절차](production.md#섹션별-제작)

## 일부 화면의 디자인 수정

1. [레퍼런스 확인](intake.md#레퍼런스-목록-확인)부터 시작해 확정된 레퍼런스 또는 기존 스타일을 확인한다. 사용자가 변경 범위에 새 후보를 여러 개 제공하면 [HTML 토너먼트](#레퍼런스-선택)에서 그 범위의 기준 한 개를 정한다.
2. 기준 화면에서 바꿀 요소, 적용할 레퍼런스 특징, 재사용할 레이아웃·콘텐츠·컴포넌트를 아트 디렉션에 남기고 해당 변경을 승인받는다. 공통 스타일 변경이 다른 화면에 영향을 주면 영향을 받는 화면을 함께 고려한다.
3. 실제 콘텐츠가 들어간 수정 시안과 필요한 모바일 상태를 보여주고 확인받는다. 자료가 변경되면 해당 화면의 시안과 필요한 에셋·모션을 다시 검토한다. 구현 뒤 기준 화면과 바뀐 화면, 연결된 기존 동선을 비교한다. [변경 범위와 브라우저 검수](review.md)
