# 신규와 수정 경로 선택

## 최초 범위 확인

1. 재개 요청은 [진행 메모](continuity.md)부터 읽는다. 새 포트폴리오 요청에는 **“이미 만들어 둔 포트폴리오가 있나요? 기존 것을 수정할지, 새로 만들지 알려주세요.”**라고 묻는다. 사용자가 이미 작업 유형을 분명하게 말했으면 해당 경로로 시작한다.
2. 신규 제작이면 아직 정하지 않은 경우 GitHub 블로그와 HTML 링크 중 형식을 확인하고 [형식과 자료 확인](intake.md)으로 이어간다. 사용자가 기존 사이트와 별개의 포트폴리오를 만들겠다고 하면 새 작업으로 기록한다.
3. 기존 사이트를 수정한다면 사이트 주소나 로컬 경로, 바꿀 화면이나 프로젝트, 원하는 결과를 확인한다. 공개 링크와 편집 가능한 저장소·로컬 소스의 경로를 연결한다. 사용자가 기준으로 지정한 배포본·브랜치·커밋·파일 상태를 우선하고, 손대기 전에 현재 로컬 변경도 확인한다. 재사용할 레이아웃·콘텐츠·미디어·동작과 수정할 항목을 작업 메모에 적는다. [기준 버전과 검수](review.md#부분-수정의-기준-버전)
4. 주소만 있으면 현재 화면을 보고 개선안을 제시할 수 있다. 실제 수정에 필요한 저장소나 HTML 소스만 요청한다. 기존 저장소·호스팅·게시 설정을 사용하고, 이전·전면 교체가 요청되면 그 대상과 범위를 확인한다.

수정 범위를 짧게 확인하고 해당 단계에 착수한다. 예를 들어 “프로젝트 상세에서 사용 기술 두 줄만 아래 문구로 교체”처럼 변경이 구체적이면 그 지시를 작업 범위로 사용한다.

## 수정 종류에 따른 진행

| 사용자가 바꾸려는 부분 | 시작 단계와 진행 방식 | 주로 협업할 역할 |
| --- | --- | --- |
| **내용** | 현재 문구와 수정 범위를 확인한다. 사용자가 준 문구를 적용하거나, 프로젝트 경험·수치·이미지를 새로 넣는 경우 그 부분의 근거만 검토한다. 보완 원고가 필요하면 전후 문구, 사실 근거, 관련 섹션을 보여주고 확인받는다. | **PM과 콘텐츠 에디터**가 원고를 주고받는다. 화면에 반영할 때는 프런트엔드 개발자에게 편집 위치와 승인 문구를 넘긴다. |
| **디자인** | 바꿀 화면이 정해지면 **레퍼런스 확인 단계**로 들어간다. 원하는 시각 효과와 기존 화면에서 지킬 부분을 함께 정하고, 해당 화면의 데스크톱·모바일 시안을 보여주어 구현 승인을 받는다. 전체 디자인 방향을 바꾸는 경우 공통 요소·상위 3개 흐름을 사용한다. | **PM과 UI 디자이너**가 레퍼런스를 정리하고, 프런트엔드 개발자가 구현을 시험한다. QA/배포가 승인 시안과 결과를 대조한다. |
| **탐색 구조·프로젝트 추가** | 바뀔 진입점과 상세 페이지를 확인하고 필요한 부분의 사이트맵과 콘텐츠를 검토한다. 새 프로젝트는 그 프로젝트의 기록과 공개 미디어를 확인한다. 새로 바뀌는 링크와 기존 복귀 동선을 검수한다. | **PM·웹 기획자·콘텐츠 에디터**가 구조와 원고를 맞춘 뒤 UI 또는 프런트엔드에 필요한 작업을 넘긴다. |
| **모션·기능** | 기존 동작, 재현 조건, 기대 동작을 확인한다. 새 모션이라면 실행 예제와 축소 모션 동작을 보여주고 효과를 확인받는다. 기존 기능 복구는 기준 버전과 비교해 검수한다. 모션과 함께 디자인 방향이 바뀌면 해당 화면의 레퍼런스도 확인한다. | **PM·프런트엔드 개발자·QA/배포**가 재현과 수정본을 확인한다. 시각 효과가 달라지는 경우 UI 디자이너와 모션 명세를 맞춘다. |
| **게시·링크** | 수정한 버전, 사이트 주소, 저장소·브랜치 또는 호스팅 경로를 확인한다. 게시가 요청되면 변경 내용과 공개 범위를 확인받고 실제 링크를 검수한다. | **PM과 QA/배포**가 대상과 승인 증거를 확인한다. |

하나의 요청에 여러 수정 종류가 있으면 공통 범위와 영향받는 화면을 한 번 정한다. 작업을 의존 순서대로 연결하고 겹치는 시안·원고·검수는 함께 보여준다. 예를 들어 소개 문장과 첫 화면 디자인을 함께 바꿀 때는 콘텐츠 에디터가 원고를 확정하고, 디자이너가 그 원고를 시안에 넣어 사용자에게 보여준다. [팀 제작과 인계](production.md)

내용만 바꾼 경우 해당 상세의 기존 레이아웃과 연결된 갤러리·영상·기록·복귀 동선을 기준본과 비교한다. 디자인이나 모션을 바꾼 경우 해당 화면의 콘텐츠와 기존 동선을 함께 비교한다. 같은 파일 안에 여러 기능이 있으면 파일 변경과 실제 브라우저 동작을 각각 확인한다. [브라우저 검수](review.md)

## 제작 중 경로 조정

1. 신규 제작과 기존 수정 중 모두, 피드백을 받으면 PM이 **달라지는 요구, 현재 단계, 승인한 결과물, 의존하는 작업**을 대조한다. 기존 작업의 진행 메모에서 계속 기록한다.
2. 영향이 시작되는 단계에서 필요한 작업을 한다. 원고만 달라지면 PM과 에디터가 다시 검토하고, 레이아웃이나 콘텐츠 길이에 영향을 주면 그 부분의 시안도 확인한다. 승인한 디자인 방향 안에서 색이나 간격을 조정하면 해당 시안부터 검토한다. 디자인 방향이나 레퍼런스가 달라지면 레퍼런스 단계에서 해당 자료를 다시 확인한다. 효과만 달라지면 모션 명세와 미리보기를 갱신한다.
3. 이미 승인한 산출물 가운데 영향이 없는 것과 기존 협업 담당자를 재사용한다. 단계 순서를 조정할 때는 필요한 자료, 다음 담당자, 사용자에게 다시 보여줄 산출물을 PM이 정리한다. 검수 범위는 변경 항목과 영향을 받을 수 있는 연결 동선으로 잡는다.
4. 바뀐 결과와 다음 행동을 사용자에게 보여주고 해당 결정의 승인을 받는다. 변경된 범위, 유효한 승인, 현재 단계와 대기 중인 요청을 [진행 메모](continuity.md)에 기록한다.
