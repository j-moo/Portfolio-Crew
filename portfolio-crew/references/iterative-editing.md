# 기존 포트폴리오의 반복 편집

## 편집 범위와 작업 원본

- 최신 지시에서 **어느 프로젝트의 어느 화면, 어느 요소**를 바꾸는지 잡는다. 목록 카드, 상세 개요 사진, 사례별 증거는 같은 이미지를 쓰더라도 별도 편집 대상이다. “나머지도 똑같이”는 승인된 순서·탐색·강조 방식을 공통화하고 각 프로젝트의 역할·수치·사진은 각 기록으로 채운다는 뜻으로 다룬다.
- 사이트 원본, 프로젝트 기록 폴더, ZIP, 배포 저장소의 역할을 구분한다. “앞으로 이 폴더에서”라는 지시가 오면 작업 메모의 기준 경로를 갱신하고 다음 편집·검사·커밋을 그곳에서 한다. pull 요청은 해당 복제본의 원격·브랜치·로컬 변경부터 확인한다. 변경을 보관했다면 위치와 복원 상태를 알린다.
- “무슨 뜻인가요?”는 쉬운 설명으로 답한다. 원고가 어렵다는 피드백이면 주체·입력·행동·결과가 보이는 말로 해당 문장을 고친다. 기록 확인 요청은 근거를 먼저 제시한다. “제가 고를게요”, “이 문장만 삭제”, “수정 전으로”는 각각 선택 대기, 지정 구절 삭제, 해당 시점의 표현·디자인 복원으로 처리한다.

## 원고와 사례

- 프로젝트 개요는 사용자가 무엇을 하는 서비스인지, 개인 역할은 직접 맡은 작업인지, 주요 기능은 그 작업이 어떻게 동작하는지, 핵심 성과는 그 결과 사용자나 시스템에서 무엇이 가능해졌는지를 각각 설명한다. 기능에 선행 관계가 있으면 데이터 준비 → 예측 → 서비스 적용처럼 실제 순서로 쓴다. 측정값은 설명하는 성과 가까이에 둔다.
- 기술 스택에는 실제 구현·선정에 사용한 기술을 둔다. 비교 실험 후보, 제안 단계, 운영 배포 여부는 해당 판단을 설명할 때 밝힌다. 기기 로그·자동 시험·개발 메모·시연 캡처의 근거 수준을 구분한다. 코드 검사 통과를 실제 서비스 성공으로, 로컬 성능을 운영 성능으로 확대하지 않는다.
- 독자가 겪는 증상이나 결정해야 했던 질문으로 사례 제목을 잡는다. 분석에서 왜 문제였는지, 가설에서 무엇을 바꾸면 나아질지, 실험에서 무엇을 고정하고 바꿨는지 설명한다. 개선 전후와 결과 코멘트는 같은 자리에서 한 번만 보여준다. 사용자가 별도 검증 범위 단락을 빼면 핵심 수치가 가리키는 조건은 결과 문장에 남긴다.
- 같은 문제의 원인들은 한 사례로 묶을 수 있다. 별도의 판단·행동·증거가 있는 예외는 분리한다. 예컨대 일반 매핑으로 49구간 중 21→48구간을 연결하고, 예약 표기를 직접 확인해 48→49구간이 됐다면 두 단계에 각각의 증가분을 쓴다. 다른 표본의 수치는 따로 설명한다. 대체 사례는 프로젝트 기록에서 고르고, 남길 만한 사례가 없으면 삭제 요청 범위에 맞춰 줄인다.
- 하이라이터는 본인이 내린 결정이나 수행한 행동을 짧게 짚는다. 특정 구절을 지정하면 렌더링되는 원문과 일치시키고 실제 강조를 확인한다. 질문형 제목, 핵심 성과 위치, 번호 표기, 색상은 해당 포트폴리오에서 승인된 방식을 따른다.

## 레퍼런스와 미디어

- 여러 레퍼런스로 미리보기를 요청하면 같은 실제 포트폴리오 내용으로 요청한 후보·화면 수를 맞춰 비교한다. 원본의 서체·색·선·컴포넌트를 살리고 배치는 사용자 콘텐츠에 맞춘다. 승인된 버전에서 글자 굵기나 한 색만 고칠 때 다른 요소까지 새로 디자인하지 않는다.
- Drive를 지정하면 기존 자료 링크와 연결된 검색을 먼저 사용한다. ZIP의 “첫 번째 사진”은 실제 이미지 항목의 순서와 파일명을 확인한다. 사용자가 고른 캡처의 UI는 보존한다. 목록의 기기 프레임에서는 화면과 베젤의 정렬, 두 기기의 크기·겹침, 카드 배경을 확인한다. 상세 개요에서는 캡션까지 포함한 이미지 높이를 본문과 비교하고 모바일의 잘림을 본다.
- 실제 장면을 요청하면 영상에서 해당 동작이 보이는 프레임을 고른다. 얼굴을 가리라는 요청은 큰 화면·작은 참가자 화면까지 처리하고 게시용 파일 자체를 눈으로 확인한다. 사례 이미지는 본문을 입증하는 화면·그래프·코드에 맞춘다. 재구성한 비교표나 테스트 요약에는 그 성격을 캡션에 적는다.

## 반영과 검수

- 사례를 이동·삭제·분리하면 본문, 목차, 해시, 연결된 증거와 캡션을 한 단위로 갱신한다. 목록에서 상세로 진입해 직접 링크, 이전·다음, 목록 복귀가 맞는지 변경 범위에 따라 확인한다. 시각 변경은 모바일과 데스크톱에서 확인하고 키보드 포커스·축소 모션을 보존한다.
- “푸시까지”는 지정 저장소에서 요청한 변경을 검사·커밋하고 원격 반영을 확인하는 데까지다. Pages 게시까지 요청되었거나 해당 푸시가 게시 단계라면 배포 완료 후 바뀐 상세 주소와 미디어를 확인한다. 결과는 실제 확인 수준에 맞춰 보고하고 바로 열리는 링크를 준다. 로컬 작업, 원격 반영, 공개 화면 확인을 구분한다.
