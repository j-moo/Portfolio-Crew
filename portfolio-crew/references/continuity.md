# 진행 저장과 재개

포트폴리오 작업은 그때까지 확인한 자료와 사용자 결정을 이어 쓴다. 진행 중인 같은 작업이나 사용자가 요청한 재개에만 해당 메모를 읽는다. 새 작업에서는 현재 요청에 있는 기존 포트폴리오 여부를 사용하고, 정보가 없으면 먼저 묻는다.

## 진행 메모 위치와 기록

- 작업을 시작한 프로젝트 폴더의 `.portfolio-crew/progress.md`를 기본 위치로 사용한다. 프로젝트별 작업 폴더를 여러 개 쓰는 경우 해당 폴더의 메모를 사용한다. 사용자가 지정했거나 이미 사용 중인 메모가 있으면 그 경로를 이어 쓴다. 같은 폴더에서 별도 포트폴리오를 시작하라는 요청을 받으면 별도 메모 경로를 정해 기존 기록을 보존한다. 어느 작업의 메모인지 모호하면 프로젝트나 메모 경로를 확인한다.
- 메인 에이전트가 작업 유형을 확인한 뒤 메모를 만들고 갱신한다. 사용자 선택·승인이 확정되거나 단계와 산출물이 바뀔 때, 다른 작업으로 전환하거나 중단하기 전에 갱신한다. 질문이 필요하면 현재 대기 항목 한 가지를 기록하고 사용자 답을 기다린다. PM과 서브 에이전트는 보고를 전달하고 메인 에이전트가 확인한 내용을 반영한다.
- 메모는 로컬 작업용으로 두고 게시 폴더와 공개 커밋 후보에서 제외한다. 자료의 위치와 승인 범위를 간단히 남기고 비밀번호·토큰이나 비공개 문서 본문은 기록하지 않는다.
- 폴더에 쓸 수 없으면 허용된 작업 경로에 메모를 남기고 재개에 쓸 위치를 알려준다. 접근 가능한 경로가 없다면 채팅에 현재 단계와 다음 행동을 남긴다. 이전 메모를 읽을 수 없는 재개 요청에는 해당 파일이나 마지막 승인 정보를 요청한다.

메모에는 다음 항목 가운데 현재 단계에 필요한 부분을 기록한다. 확인하지 않은 값은 대기 상태로 표시한다.

| 기록 항목 | 남길 내용 |
| --- | --- |
| 작업 | 프로젝트 이름과 작업 폴더, 사용자 목표, 신규 제작·기존 수정 여부, 제작 형식, 저장소 또는 호스팅 대상, 기준 버전과 변경·보존 범위 |
| 현재 위치 | 진행 중인 단계, 완료한 작업, 진행·입력 대기·일시 중단·완료 중 현재 상태 |
| 확정한 자료와 결정 | 지원 직무나 공통 목적, 확인한 기록·레퍼런스의 경로와 목록, 상위 3개, 선택한 콘텐츠와 근거, 승인한 시안·효과·배포 범위 |
| 산출물과 인계 | 사용자에게 보여준 버전·커밋·캡처, 아트 디렉션과 에셋 목록의 위치, 현재 섹션과 기준 레퍼런스, 시안·모션 검토 및 시각 검수 라운드, 담당자 |
| 대기 중인 결정 | 사용자가 마지막으로 받은 질문, 승인할 산출물과 범위, 사용자가 답한 뒤 할 다음 행동 |
| 실행 상태 | 저장소 생성·푸시·게시처럼 진행 중이거나 완료한 작업의 대상, 시작 여부, 실제 확인 결과나 연결 주소 |

저장소 생성·푸시·게시 전에는 이미 허용된 대상과 다음 행동을 기록한다. 완료 뒤 결과와 확인 근거를 남긴다. 실행 도중 중단되면 재개할 때 대상 저장소, 원격 브랜치나 게시 상태를 조회한다. 끝난 작업은 그 결과를 메모에 반영해 이어 쓰고, 재시도 여부는 확인한 상태와 사용자 승인 범위로 판단한다. 결과를 확인할 수 없으면 확인에 필요한 정보나 접근 권한을 요청한다.

## 다른 요청을 받았을 때

| 사용자 요청 | 진행 방식 |
| --- | --- |
| “왜 이 라이브러리를 써요?”처럼 단계 중에 잠깐 물어본다 | 질문에 답하고 진행 중이던 단계와 대기 항목을 유지한다. 계속할 작업이 승인되어 있으면 그 작업을 이어가고, 선택이나 승인을 기다렸다면 같은 항목을 기다린다. |
| “모바일 제목만 바꿔줘”처럼 포트폴리오에 수정 요청을 한다 | 같은 작업에서 [제작 중 경로 조정](routing.md#제작-중-경로-조정)을 적용한다. 영향받는 단계와 담당자를 골라 수정하고, 다시 확인할 승인과 재개 지점을 기록한다. |
| “이건 잠깐 멈추고 다른 일을 먼저 해줘”처럼 별도 작업으로 전환한다 | 현재 위치와 대기 중인 질문을 저장하고 포트폴리오를 일시 중단 상태로 둔다. 새 요청을 처리한다. 다른 일을 끝낸 뒤 이어 달라고 함께 요청받았으면 작업을 마친 뒤 포트폴리오를 재개한다. |
| “아까 포트폴리오 이어서 해줘”라고 하거나 대기 중이던 포트폴리오 질문에 명확히 답한다 | 해당 작업의 메모를 읽고 아래 재개 절차를 따른다. 어떤 작업에 대한 응답인지 모호하면 현재 대기 항목을 짧게 보여주고 확인한다. |

진행 상황을 묻는 말, 별도 작업에 대한 확인, 일반적인 “이어서 해줘”는 특정 시안이나 게시를 승인하는 말과 구분한다. 사용자가 해당 산출물과 범위를 명확히 승인한 경우 그 결정을 기록하고 다음 행동을 진행한다.

## 돌아왔을 때 재개하는 순서

1. 같은 채팅에서는 사용자가 돌아온 작업과 최신 응답을 확인하고, 새 채팅에서는 해당 프로젝트의 작업 폴더 또는 지정한 메모를 확인한다. 기존 메모를 읽고 최신 메시지와 실제 산출물을 대조한다. 사용자가 최신 요청에서 바꾼 범위를 먼저 반영한다.
2. 확정했던 선택과 승인 범위, 다음 행동을 복원한다. 경로와 이름이 같은 산출물도 기록한 버전·커밋·캡처 등으로 실제 보여준 결과와 대조한다. 달라진 부분을 보여주며 영향받은 결정만 다시 확인한다. 어느 버전을 이어갈지 확인하기 어렵다면 사용자에게 확인할 파일이나 결정을 구체적으로 요청한다.
3. 현재 단계와 다음 행동을 한 줄로 알린다. 대기 메시지에 실제로 답이 왔다면 처리한다. 사용자 결정이 남아 있으면 현재 항목 하나만 다시 물은 뒤 응답을 기다린다. 남은 작업은 승인된 범위에서 진행한다.
4. 재개한 역할에는 마지막에 확인된 산출물과 남은 일을 넘긴다. 이전 에이전트를 다시 사용할 수 있으면 현재 버전과 함께 인계하고, 새로 맡겨야 하면 해당 역할에만 필요한 지침을 전달한다. 재개 결과와 다음 대기 항목을 같은 메모에 기록한다.
