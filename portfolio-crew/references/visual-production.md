# 비주얼·모션 제작과 인계

레퍼런스에서 보존할 특징을 화면에서 확인 가능한 기준으로 정하고, 실제 콘텐츠가 들어간 화면에서 검증한다. 신규 제작은 첫 화면과 대표 상세를, 일부 수정은 기준 사이트와 영향받은 화면을 대조한다. 디자인, 구현, QA는 [단계별 승인](production.md#단계별-승인)을 공유한다.

## 모션 피드백을 실행 예제로 옮기기

“드로잉 느낌”처럼 같은 이름으로 여러 동작을 가리킬 때는 화면에서 움직일 대상·영역·방향·끝 상태를 구체화한다. 예를 들어 전체 제목을 좌→우로 진행하며 위아래로 쓸어 드러내는 요청이라면 여러 줄에 하나의 마스크를 적용하고, 지울 때 같은 궤적을 역재생한다. 사용자가 뺀 연필·지우개 소품도 시안과 구현에서 함께 뺀다. 첫 프레임, 중간, 종료 및 다음 섹션을 실제 재생으로 확인한다. 모바일 줄바꿈·행간, 클릭이나 스크롤로 건너뛰기, 자동 이동 여부, 축소 모션에서의 읽기와 탐색을 승인된 의도에 맞춘다.

## 기본 시안과 모션

신규 제작은 첫 시안과 미리보기에서 아래 세 가지를 설계한다. UI 디자이너는 승인된 아트 디렉션과 어울리는 적용 위치를 정하고, 프런트엔드 개발자는 승인 이후 실제 화면 크기에서 텍스트와 페이지 모션을 시험한다. 사용자가 요청한 정적 표현이나 특정 효과가 있으면 그 결정에 맞춘다. 기존 사이트 수정은 이번에 바꾸는 디자인이나 동작에 적용한다.

| 기본 항목 | 처음 보여줄 산출물 |
| --- | --- |
| 포인트 컬러 | 제목·링크·버튼·프로젝트 근거 중 강조할 요소에 색을 적용한 시안과 색상 역할. [포인트 컬러 적용](#포인트-컬러-적용) |
| 텍스트 애니메이션 | 실제 제목이나 핵심 문구를 사용한 미리보기. 예를 들어 제목의 짧은 마스크 리빌이나 키워드 하이라이트. |
| 페이지 모션 | 프로젝트에 접근하는 실제 화면의 전환이나 조작을 보여주는 미리보기. 예를 들어 대표 이미지가 스크롤에 따라 드러나거나 상세 목차의 현재 위치가 바뀌는 장면. |

첫 화면의 정보 위계와 모바일 탐색에 맞춰 [후보](#모션-후보와-적용-조건)에서 효과를 고르고, 시안 확인 뒤 모션 미리보기를 사용자에게 보여준다.

## 디자인 품질 규칙

사용자가 선택한 스타일의 핵심을 실제 제목, 프로젝트 이미지, 콘텐츠 분량에 맞춰 구현한다. 다음 기준은 신규 디자인과 영향을 받는 재설계 화면에 적용한다. 레퍼런스가 다른 방향을 요구하면 아트 디렉션에 어디서 어떤 이유로 그 특성을 채택하는지 적고 사용자 확인을 받는다.

- **타이포그래피.** 본문용과 제목용 웹폰트의 굵기·글립·라이선스를 확인해 실제로 불러오고 대체 스택을 지정한다. 제목용은 승인한 컨셉에 맞는 서체를 고른다. 제목과 본문의 크기 차이를 뚜렷하게 두고, 첫 제목의 크기는 `clamp()`로 조정하면서 긴 한글·영문 실제 문구의 줄바꿈, 높이, 375px 화면의 넘침을 확인한다.
- **구도.** 대표 장면에서 시선의 초점을 하나 정하고, 신규 디자인의 적어도 한 장면에서 비대칭 열·그리드에 걸친 이미지·통제된 겹침 중 컨셉에 어울리는 방법을 적용한다. 키보드 이동과 모바일 읽기 순서가 자연스럽게 유지돼야 한다. 소개, 프로젝트 목록, 상세 증거는 각 목적에 맞춰 배치·밀도·정렬을 바꾸고, 공통 글꼴·색·여백 토큰으로 연결한다. 의도한 여백과 이미지의 비율을 시안에서 보여준다.
- **색과 표면.** 기본 팔레트는 3~5개 역할 색으로 시작하고 강조색은 한 화면의 중요한 지점 한두 곳에 둔다. 대표 장면의 인상은 실제 이미지, 별도로 제작한 질감이나 목업, 깊이를 만드는 색·레이어 중 컨셉에 필요한 요소로 만든다. 선택한 재질의 크롭, 레이어 순서, 투명도와 표시 크기를 시안과 맞춘다.
- **상태와 문구.** 각 조작 요소의 기본·호버·키보드 포커스와 해당되는 선택 상태를 디자인한다. 버튼과 카드마다 행동이 읽히게 하고, 아이콘은 승인한 세트에서 가져와 의미를 전달한다. 화면에 올라가는 제목과 설명은 실제 프로젝트의 역할·행동·검증을 담는다. [포트폴리오 작성 기준](portfolio-writing.md)

### 피할 기본값

시안과 구현을 검토할 때 아래 조합을 찾아 고친다. 특정 조합을 쓰는 경우에는 사용자가 승인한 컨셉의 적용 위치와 의도를 아트 디렉션에 기록한다.

- 보라·파랑 그라데이션이나 네온 글로우를 화면 전반의 기본 강조로 사용한다.
- Inter·Roboto·Arial·system-ui를 별도의 서체 결정 없이 헤드라인에 사용하거나, 이모지를 조작 아이콘으로 사용한다.
- 모든 섹션을 가운데 정렬하고, 정보가 다른 섹션까지 동일한 3열 둥근 카드로 구성한다.
- 카드와 버튼마다 똑같은 그림자와 위로 뜨는 호버를 반복하거나, 유리·그라데이션·그림자 효과를 무관한 곳까지 씌운다.
- 일반적인 개발자 소개 문구, 의미 없는 배지, 회색 박스만으로 대표 이미지를 채운다.

## 포인트 컬러 적용

사용자가 고른 레퍼런스를 바탕으로 배경·본문과 포인트 컬러의 역할을 정한다. 가장 강조할 링크나 행동, 먼저 읽을 키워드, 프로젝트의 증거 등 강조 대상을 정하고 포인트 컬러를 반복해서 사용할 위치를 시안에 표시한다. 다른 컬러가 필요하면 보조 강조나 상태 표시처럼 역할을 정한다.

색상값과 적용 대상을 함께 넘긴다. 실제 제목·카드·링크와 이미지 위에서 대비를 확인하고, 클릭 가능 여부와 선택·포커스 상태를 밑줄·테두리·레이블 같은 단서로도 표시한다.

## 이미지 에셋 제작

신규·재설계의 이미지 시안과 배경·새 래스터 에셋은 `imagegen` 스킬과 내장 도구로 제작한다. 선택 전 비교 시안은 후보마다 해당 원본을 시각 입력으로 쓰며, 구현용 에셋에는 승인된 시안과 기준 원본을 쓴다. 필요한 배경은 최종 레퍼런스의 색온도와 빛, 표면, 여백을 바탕으로 독립 에셋으로 만든다. 이미지 시안은 구현 승인 전에 준비한다. 디자이너에게 도구가 없으면 전송 가능한 파일 경로, 사용 장면과 역할, 생성 명세를 메인 에이전트에게 넘긴다. 메인 에이전트는 실제 이미지가 도구의 시각 입력으로 첨부됐는지 확인하고 결과 파일을 작업 폴더에 저장해 디자이너에게 돌려준다.

1. **승인한 시안에서 제작 목록을 만든다.** `docs/asset-list.md`에 승인 시안 위치, 파일명, 사용할 섹션, 입력 이미지와 제작 방식, 필수 여부, 파일 규격과 공개 범위를 적는다. 사용자 자료가 필요하면 현재 섹션의 파일과 넣을 에셋 폴더의 절대 경로를 안내한다.
2. **대표 장면을 만드는 레이어를 실제 파일로 준비한다.** 배경, 질감, 오브젝트와 제품 프레임은 최종 레퍼런스와 이를 바탕으로 만든 승인 시안으로 생성한다. 기존 제작 에셋은 같은 디자인에 맞게 이미 승인됐을 때 재사용한다. 승인 시안에 로컬 한정 자료가 합성됐으면 전송 가능한 레이어로 에셋을 생성한다. 내용·구도·빛·표면·색·크롭과 필요한 투명 영역을 지정한다. 본문과 링크·버튼을 HTML로 배치할 공간을 둔다. 서비스 화면·동작·성과는 공개 가능한 실제 캡처나 시연으로 보여준다.
3. **승인 시안과 비교한 제작본을 작업 폴더에 저장한다.** 생성본을 열어 질감·팔레트·경계·글자·왜곡을 확인하고, 중요한 차이는 바꿀 요소를 지정해 다시 생성한다. 프로젝트에서 사용하는 최종 파일을 기본 생성 위치에서 프로젝트의 `assets/` 또는 기존 에셋 폴더로 복사하고 실제 파일을 연다. 기존 자산과 겹치면 버전이 붙은 파일명을 사용한다. 명세에 생성 방식과 최종 프롬프트, 파일 경로, 표시 비율, 데스크톱·모바일 크롭, 겹침 순서, 대체 텍스트·장식 여부를 기록한다.
4. **도구나 필수 파일이 없는 경우 화면 기준을 유지한다.** 시각 입력 기능이 없으면 레퍼런스를 직접 보고 정적 디자인 도구에서 시안을 만든다. 이미지 생성만 가능하면 합의한 구도와 팔레트로 배경 등 생성 에셋을 만들고 어떤 방식으로 만들었는지 알린다. 정적 시안도 동일한 아트 디렉션 승인 단계에서 보여준다. 생성 자체가 불가능하면 요청한 생성 에셋은 대기 상태로 기록하고, 사용이 승인된 실물 대안을 함께 확인받을 수 있다. CLI는 사용자가 선택한 경우에만 `imagegen` 지침에 따라 사용한다. 필수 이미지 대기 중에는 승인 후 구조 초안에서 놓일 위치와 비율까지만 확인한다.

배경의 데스크톱·모바일 크롭과 텍스트가 놓일 영역을 시안에 표시한다. CSS 구현을 비교한 뒤 시각 차이가 남은 컴포넌트도 생성 에셋으로 보완한다. 레이아웃·가변 콘텐츠·동작은 실제 HTML로 유지한다. [컴포넌트 검수](component-production.md#제작과-컴포넌트-검수)

## 모션 후보와 적용 조건

시안의 어떤 콘텐츠를 어떻게 읽게 할지 먼저 정한 뒤 해당 장면의 효과를 고른다. PM은 선택한 효과를 실제 콘텐츠가 든 미리보기로 보여주고 터치·키보드·축소 모션에서의 동작을 설명한다.

| 화면의 목적 | 검토할 효과와 적용 기준 |
| --- | --- |
| 첫 화면 제목이나 핵심 문장을 소개 | 마스크 리빌(가려진 영역에서 등장), 블러 인(흐림에서 선명해짐), 스태거(단어나 줄이 순서대로 등장) 중 읽는 순서에 맞는 효과를 검토한다. 짧은 타자기 효과를 쓸 때도 이름·직무·핵심 메시지는 처음부터 읽을 수 있게 제공한다. |
| 프로젝트 목록에서 읽는 흐름 보조 | 페이드 인(서서히 표시), 슬라이드 업(아래에서 위로 이동), 스크롤 리빌(화면에 들어올 때 등장)을 카드와 섹션의 읽는 순서에 맞춘다. 패럴랙스는 배경 등의 깊이 표현에, 스티키는 상세 목차나 시연 설명의 기준을 유지하는 데 검토한다. 작은 화면과 확대 상태에서 콘텐츠가 가려지거나 스크롤에 갇히는지 확인한다. |
| 링크나 카드의 조작 단서를 보강 | 호버 리프트(포인터를 올리면 살짝 들림)나 마그네틱 버튼(포인터 방향으로 장식이 움직임)은 포인터 사용 환경에서 시험한다. 실제 클릭 영역을 유지하고, 터치·키보드에서도 상태와 이동이 분명하게 보이게 한다. |
| 핵심 단어, 숫자, 장식에 강조 | 형광펜 하이라이트, 빛이 한 번 지나가는 효과, 검증된 수치의 카운트업을 검토한다. 수치에는 실제 값·단위·조건을 처음부터 제공하고, 움직이는 숫자는 시각적 효과로 취급한다. 문자 스크램블, 단어 교체, 전광판식 전환, 글리치와 마퀴는 장식이나 짧은 보조 영역에서 검토한다. 반복 효과를 적용하면 정지할 수 있는 방법과 축소 모션의 정적 상태를 준비한다. |

개발자는 애니메이션 중에도 보조 기술이 제목과 링크 이름을 온전히 읽을 수 있게 한다. 글자를 분할하거나 숫자를 바꾸는 방식은 의미가 있는 원문·최종 값을 접근 가능한 HTML에서 유지하고, 장식용 복제 요소는 보조 기술에서 제외한다. QA는 애니메이션이 진행 중인 때와 멈춘 때의 내용과 포커스를 대조한다.

명세 예시로 **대표 프로젝트 카드에 스크롤 리빌과 스태거를 적용**하는 경우, 카드 묶음이 처음 들어올 때 각 카드를 조금 아래에서 제자리로 이동시키며 한 번 표시한다. 예를 들어 카드당 260ms, 카드 사이 60ms 간격을 브라우저에서 시험한다. 축소 모션 설정이나 스크립트 로드 실패 시 모든 카드와 링크를 기본 상태로 제공한다. 실제 시간과 움직임은 시안을 기준으로 조정하고 사용자에게 미리보기로 확인받는다.

## 모션 방식과 의존성 선택

UI 디자이너와 프런트엔드 개발자는 효과별 목적과 복잡도를 보고 도구를 고른다. 포트폴리오의 주요 장면에서는 동일한 시안으로 짧은 실행 예제를 만들어 의도한 리듬과 사용성을 확인한다.

장면의 특징이 스크롤 타임라인, 가림막에서 드러나는 글자, 여러 요소의 연쇄 전환이라면 시안의 속도와 전환을 브라우저에서 재현하는 방식으로 시험한다. 예제에는 실제 문구·이미지, 효과의 시작·끝 상태, 라이브러리와 실패할 때 표시할 정적 화면을 함께 넣는다. 짧은 색상 변화와 포커스 표시는 네이티브 상태에 연결한다.

| 구현할 효과 | 우선 검토할 방식 |
| --- | --- |
| 포커스 표시나 짧은 호버 색상 변화 | CSS의 상태 스타일과 짧은 전환 |
| 여러 요소가 연결된 타임라인, 스크롤 진행에 따라 움직이는 장면, 구간 고정·순차 등장 | **GSAP + ScrollTrigger**로 타임라인과 스크롤 조건을 검증한다. [ScrollTrigger 공식 문서](https://gsap.com/docs/v3/Plugins/ScrollTrigger/) |
| 스프링 기반 카드 상호작용, 제스처, 컴포넌트 상태·레이아웃 전환 | **Motion**을 검토하고 해당 기능의 프레임워크 또는 JavaScript 지원을 확인한다. [Motion 공식 문서](https://motion.dev/docs) |

- 기존 프로젝트에 패키지 관리와 빌드가 있으면 선택한 패키지와 버전을 기록하고 잠금 파일로 재현한다. 빌드 없는 정적 HTML이면 공식 설치 안내에서 CDN 또는 로컬 배포 방식을 확인하고 실제로 확인한 버전을 고정한다. GSAP과 플러그인을 함께 쓸 때는 호환 버전과 로딩 순서를 확인한다. [GSAP 설치](https://gsap.com/docs/v3/Installation/) · [Motion 설치](https://motion.dev/docs/quick-start)
- 개발자가 실행 시험과 호스팅 환경을 근거로 패키지·CDN·로컬 파일 중 한 방식을 제안한다. QA는 로딩과 실패 시 동작을 확인하고, PM은 선택한 버전과 방식을 제작 기록에 남긴다. 전달 방식을 변경해도 승인된 화면·효과·공개 범위를 유지하면 그 승인을 사용해 같은 기준으로 재검수한다. 이 범위를 바꿔야 하면 달라지는 모습을 보여주고 해당 변경을 확인받는다.
- 모션 명세에 입력과 트리거, 초기·종료 상태, 시간과 이징·순차 간격, 역방향·연속 입력, 모바일·키보드·축소 모션 설정을 적는다. 의존성 이름과 버전, 로딩 방식, 실패 때의 동작을 같이 넘긴다.
- 외부 스크립트가 지연되거나 로드에 실패해도 제목, 콘텐츠, 탐색 링크가 브라우저에서 작동하도록 기본 화면을 유지한다. 축소 모션에서는 콘텐츠를 즉시 표시하거나 승인된 간단한 상태 전환을 사용한다. 크기 변경과 화면 재진입에서 리스너나 타임라인이 중복되면 정리한다.

## 에이전트 간 시안 검토와 반영

1. **UI 디자이너 → 개발자·에디터.** 원본 레퍼런스와 승인 시안의 이미지 파일, 실제로 사용할 에셋과 배치·크롭·라이브 텍스트 영역, 웹폰트·색상값을 전달한다. 개발자는 실제 파일을 열어 확인한다. 에디터는 검증 자료의 출처와 사용 범위를 회신한다.
2. **개발자 → 디자이너·QA.** 신규·재설계에서는 아트 디렉션 승인 후 적용하기 어려운 재질이나 동작을 격리된 미리보기에서 시험한다. 기존 화면의 효과만 바꿀 때는 그 화면으로 미리보기를 만든다. 기준 화면과 브라우저 결과의 차이, 패키지나 CDN 선택, 필요한 파일과 대체 동작을 돌려준다. 사용자 승인 후 선택한 효과를 제작 사이트에 넣는다.
3. **디자이너·QA → PM.** 디자인 승인 전에는 정적인 이미지 시안을 원본과 비교한다. 승인 후에는 섹션의 격리 미리보기에서 제안한 효과를 시험하고, 구현부터는 승인된 이미지와 효과를 기준으로 검수한다. 같은 화면 폭에서 질감·크롭·타이포그래피와 모션 타이밍의 구체적인 차이, 축소 모션·CDN 실패 시 동작을 캡처나 영상으로 남겨 담당자에게 전달한다.
4. **PM → 메인 에이전트와 사용자.** 실제 콘텐츠가 든 영향 범위의 시안, 해당하는 효과 미리보기, 확인한 차이와 남은 선택을 전달한다. 사용자에게는 현재 승인받을 시안 또는 모션을 보여준다. 여러 화면에 적용하는 계획이면 승인받은 대표 화면과 효과를 해당 범위에 확장한다.

PM은 승인된 시안과 모션, 사용한 에셋, 각 섹션의 시각 검수 결과를 기록한다. 나머지 섹션도 승인한 기준에서 각각 구현하고 검수한다. [섹션별 제작](production.md#섹션별-제작)

예를 들어 첫 화면 레퍼런스의 종이 질감과 순차 등장이 중요하다면, 디자이너가 종이결 배경을 별도 이미지로 만들고 제목과 카드의 글자를 HTML로 배치한다. 개발자는 카드가 스크롤 구간에 맞춰 순차 등장하는 장면을 GSAP과 ScrollTrigger로 시험해 보여준다. QA는 같은 화면 폭에서 질감과 크롭을 대조하고, 작은 화면과 축소 모션 설정에서도 카드와 링크가 바로 읽히는지 확인한다.
