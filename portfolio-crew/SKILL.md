# Portfolio Crew

사용자가 자료와 결과를 확인하며 포트폴리오를 제작하거나 수정하는 절차다. 메인 에이전트는 사용자와 소통하고, PM 서브 에이전트는 필요한 업무, 검수와 담당자 간 인계를 관리한다.

포트폴리오 요청을 받으면 [진행 저장과 재개](references/continuity.md)를 확인한다. 같은 작업의 진행 메모가 있으면 현재 단계와 승인한 결과를 읽고 최신 요청을 반영한다. 새 요청이라면 먼저 **기존 포트폴리오가 있는지, 기존 것을 수정할지 새로 만들지** 확인한다. 사용자가 이미 명확히 알려준 답은 기록하고 다음에 필요한 정보만 묻는다. [신규와 수정 경로 선택](references/routing.md)

## 작업 경로

- **신규 제작**은 아래 기본 단계를 사용한다. 사용자가 이미 준 정보나 승인한 자료를 적용하고, 제작 중 피드백이 오면 변경의 영향을 받는 단계부터 이어간다.
- **기존 포트폴리오 수정**은 현재 사이트의 편집 소스·기준 버전과 바꿀 부분·보존할 부분을 확인한다. 디자인은 [레퍼런스 확인](references/intake.md#레퍼런스-목록-확인), 내용은 [PM과 콘텐츠 에디터의 검토](references/routing.md#수정-종류에-따른-진행)에서 시작한다. 요청을 이루는 데 필요한 단계와 역할을 선택하고, 변경한 화면과 이어진 기존 동선을 검수한다.

## 신규 제작의 기본 단계

1. 사용자에게 **GitHub 블로그**와 **HTML 링크** 중 하나를 고르게 한다. GitHub 블로그라면 사용할 저장소를 확인하거나 새 저장소를 준비한 후 프로젝트 기록을 요청한다. HTML 링크라면 프로젝트 기록 단계로 이동한다. [형식 선택과 저장소 준비](references/intake.md#형식-선택과-저장소-준비)를 따른다.
2. 프로젝트 기록 경로를 요청하고 실제 기록을 열어 확인한다. 발견한 프로젝트 목록을 사용자에게 보여주고 맞는지 묻는다. 잘못된 경로나 누락이 있으면 새 경로를 받거나 자료를 넣을 폴더를 제공한 뒤 다시 확인한다. 사용자가 목록을 승인하면 진행한다. [프로젝트 기록 확인](references/intake.md#프로젝트-기록-확인)을 따른다.
3. 로컬 디자인 레퍼런스 경로를 우선 요청하고 10장 이상을 권한다. 열어 본 자료의 목록을 제시하고 사용자 확인을 받는다. 잘못된 경로나 누락이 있으면 지정한 폴더에 자료를 넣도록 안내하고 승인받을 때까지 다시 확인한다. [레퍼런스 목록 확인](references/intake.md#레퍼런스-목록-확인)을 따른다.
4. 확인된 레퍼런스를 한 장씩 분석해 기록하고 공통 요소로 기본 디자인과 UI를 정한다. 분석과 기본안을 보여준 뒤 사용자에게 가장 마음에 드는 **3개**를 고르게 한다. 선택한 레퍼런스의 특징을 매핑해 제작에 사용할 디자인 방향을 확정한다. [레퍼런스 분석과 디자인 결정](references/design.md)을 따른다.
5. **PM, 웹 기획자, 콘텐츠 에디터, UI 디자이너, 프런트엔드 개발자, QA/배포** 서브 에이전트를 생성한다. [팀 제작 절차](references/production.md)에 연결된 각 역할의 실무 지침과 이번 작업의 승인된 입력·산출물·인계 대상을 해당 에이전트에게 전달한다. PM이 단계마다 산출물과 승인 항목을 정리한다.
6. 기록에 근거한 콘텐츠 후보를 프로젝트별로 보여주고 사용자에게 포함할 항목을 고르게 한다. UI 디자이너와 프런트엔드 개발자가 레퍼런스에 맞는 이미지 에셋과 모션을 함께 설계하고 시험한다. 실제 시안과 효과 미리보기를 보여주고 피드백과 승인을 받아 반영한다. [비주얼·모션 제작](references/visual-production.md)과 [단계별 승인](references/production.md#단계별-승인)을 따른다.
7. 실제 브라우저에서 검수하고 사용자 승인 범위에서 선택한 형식의 링크를 제공한다. [검수 가이드](references/review.md)와 [최종 링크 제공](references/production.md#최종-링크-제공)을 따른다.

## 승인과 재개

- 이미 해당 단계에 명확하게 답변한 정보는 재사용한다. 질문할 때는 지금 승인할 목록이나 결과물과 사용자에게 필요한 응답을 함께 보여준다.
- 필요한 자료·디자인 선택과 제작 단계 승인은 현재 보여준 결과를 기준으로 받는다. 응답을 기다리는 동안 해당 단계에서 허용된 작업을 수행한다.
- 사용자가 수정이나 추가를 요청하면 [제작 중 경로 조정](references/routing.md#제작-중-경로-조정)을 따라 영향을 받은 자료·화면·효과와 승인 지점을 확인한다. 수정 결과를 보여주고 그 지점부터 이어간다.
- 단계가 바뀌거나 사용자 응답을 기다리기 전에 작업 폴더의 `.portfolio-crew/progress.md`를 갱신한다. 중간 질문, 다른 작업, 일시 중단으로 대화가 바뀌면 현재 단계와 대기 항목을 저장하고 최신 요청을 처리한다. 사용자가 포트폴리오로 돌아오면 메모에 기록한 지점과 기존 승인을 사용한다. [진행 저장과 재개](references/continuity.md)
