# Portfolio Crew

메인 에이전트가 PM으로 작업 범위, 역할, 통합 결과를 책임진다. 결과물에서 독자가 지원자의 역할, 직접 내린 기술적 판단, 그 판단을 뒷받침하는 결과를 찾을 수 있어야 한다.

## 요청의 범위 정하기

- 채용 담당자나 심사위원이 확인해야 할 내용, 지원 직무, 제출 규칙, 대상 사이트와 산출물을 파악한다. 사용자 지정 프로젝트, 프로필 문구, 레퍼런스, 기술 스택, 공개 조건을 기록한다. 불명확한 사항은 자료를 먼저 확인하고 결과에 영향을 주는 질문만 취합한다.
- 신규 제작이나 전면 개편은 [제작과 인계](references/production.md)를 따른다. 참고 사례 조사가 범위에 있다면 실제 사이트나 당사자 자료를 열어 독자가 무엇을 어디서 확인할 수 있는지 분석하고, 그 관찰을 해당 포트폴리오의 구성과 검수 기준으로 옮긴다.
- 부분 수정은 사용자가 지정한 기준을 우선한다. 현재 브랜치나 작업본을 기준으로 삼을 때는 커밋에 포함되지 않은 기존 변경도 확인한다. 수정할 진입점과 파일, 보존할 동선과 콘텐츠를 먼저 기록하고 해당 부분만 고친다. 필요하면 [변경 범위와 브라우저 검수](references/review.md)의 도구를 사용한다.

## 작업 분담과 대표 흐름

서브 에이전트를 사용할 수 있으면 신규 제작의 웹 기획자와 콘텐츠 에디터를 병렬로 배정한다. PM은 두 결과를 연결하고, UI·모션 설계와 프런트엔드 구현의 인계 내용을 맞춘다. QA는 가능하면 구현과 독립적으로 맡긴다. 부분 수정에는 필요한 역할만 배정한다. 위임이 제한되면 메인 에이전트가 해당 역할을 수행한다.

각 담당자에게 읽을 자료, 편집 범위, 산출물, 검수 조건을 전달한다. 같은 파일을 다룰 때는 담당자를 한 명으로 정하거나 작업 순서를 정한다. PM이 실물 산출물과 검수 근거를 확인하고 다음 작업으로 이어간다. 사용자가 정한 확인 지점까지는 작업을 이어간다.

신규 제작과 전면 개편은 **실제 콘텐츠가 들어간 첫 화면, 핵심 전환 한 장면, 대표 프로젝트 상세 한 편**을 먼저 브라우저에서 연결한다. 데스크톱·모바일 화면, 실제 조작 녹화, 상세 원고와 출처를 함께 검토한 뒤 합의한 규칙을 나머지 화면에 적용한다. 디자인과 모션의 연결은 한 구현 담당자가 책임진다.

## 결과와 공개 검수

- 상세 첫 부분에서 본인의 역할, 구체적인 문제, 내린 판단, 검증 결과가 이어지게 쓴다. 팀 결과와 개인 작업을 각각 표시하고, 수치에는 측정 조건, 비교 기준, 출처를 붙인다. AI 활용은 해당하는 경우 맡긴 작업, 본인의 수정이나 검증, 확인된 결과를 보여준다. [프로젝트 기록 편집 기준](references/production.md)을 참고한다.
- [검수 절차](references/review.md)에 따라 실제 브라우저에서 화면과 동선을 확인한다. 모션의 자연스러움은 실제 조작 녹화로 검토한다. 원고만 고친 경우에도 갤러리, 영상, 기록, 뒤로가기 등 영향을 받을 수 있는 기존 동선을 확인한다.
- 공개 전 팀 자료, 외부 저작물, 개인정보의 사용 범위와 제출 규칙을 확인한다. 허용된 범위에서 커밋·푸시·배포를 진행하고, 공개 링크는 로그인하지 않은 상태에서 검증한다. 최종 보고에 미검증 항목과 결과물 링크를 포함한다.
