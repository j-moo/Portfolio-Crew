# Portfolio Crew

사용자가 자료와 결과를 확인하며 포트폴리오를 제작하거나 수정하는 절차다. 메인 에이전트는 사용자와 소통하고, PM 서브 에이전트는 필요한 업무, 검수와 담당자 간 인계를 관리한다.

## 기존 사이트를 이어서 편집할 때

대화에서 프로젝트와 수정 대상이 정해져 있으면 [반복 편집 지침](references/iterative-editing.md)부터 적용한다. 사용자가 지정한 최신 폴더, 선택한 사진·문구, 되돌린 디자인과 배포 범위를 이어받는다. 한 문장 삭제, 사진 교체, 사례 순서 변경처럼 결과가 명확한 요청은 바로 편집하고 검증한다. 사용자가 자료를 확인해 달라고 하거나 용어의 뜻만 물으면 먼저 근거 또는 설명을 답한다. 사용자가 직접 고르겠다고 한 자료는 후보를 보여주고 그 선택을 기다린다.

## 질문은 한 번에 한 가지

1. 새 요청에서 기존 포트폴리오 여부가 정해지지 않았으면 첫 응답을 **“이미 만들어 둔 포트폴리오가 있나요?”**라는 질문으로 마치고 답을 기다린다. 사용자가 답하기 전의 작업은 스킬 지침 읽기와 현재 질문에 한정한다.
2. 한 응답에서는 **현재 단계에서 필요한 입력이나 결정 하나만** 요청한다. 예를 들어 형식을 묻는 응답은 GitHub 블로그와 HTML 링크 중에서만 고르게 한다. 해당 질문을 보낸 뒤 그 응답을 마치고 사용자가 답하면 다음 단계로 간다. 사용자가 한 번에 여러 답을 먼저 줬다면 그 내용을 기록해 각 단계에서 사용한다.
3. 프로젝트 기록을 살펴볼 때는 사용자가 이번 작업의 기록 위치로 직접 지정한 폴더·파일·링크만 열어 확인한다. 위치가 필요하면 경로 한 가지만 묻고 답을 기다린다. 이전에 알고 있던 폴더와 연결된 저장소를 사용할 때도 이번 작업의 자료로 지정받는다. [질문 순서](references/routing.md#최초-범위-확인) · [프로젝트 기록 확인](references/intake.md#프로젝트-기록-확인)

진행 중인 같은 작업이거나 사용자가 재개를 요청하면 [진행 저장과 재개](references/continuity.md)를 따른다. 현재 단계에서 이미 확인한 답을 적용하고, 남은 결정은 같은 방식으로 한 가지씩 확인한다.

## 작업 경로

- **신규 제작**은 아래 기본 단계를 사용한다. 사용자가 이미 준 정보나 승인한 자료를 적용하고, 제작 중 피드백이 오면 변경의 영향을 받는 단계부터 이어간다.
- **여러 역할이 필요한 기존 사이트 개편**은 현재 사이트의 편집 소스·기준 버전과 바꿀 부분·보존할 부분을 확인한다. 디자인은 [레퍼런스 확인](references/intake.md#레퍼런스-목록-확인), 내용은 [PM과 콘텐츠 에디터의 검토](references/routing.md#수정-종류에-따른-진행)에서 시작한다. 요청을 이루는 데 필요한 단계와 역할을 선택하고, 변경한 화면과 이어진 기존 동선을 검수한다.

## 기본 제작 기준

- **구성과 원고.** 신규 제작에는 [공통 콘텐츠 템플릿](references/portfolio-writing.md#공통-콘텐츠-템플릿)을 적용한다. 랜딩·소개·기술·교육·목록과 각 프로젝트 상세의 항목 및 읽기 흐름을 이어 쓴다. 화면 분할·열·카드·이미지 배치·전환 효과는 사용자 레퍼런스를 보고 새로 설계한다. 본인이 구현한 범위, 기술을 선택한 이유, 문제 해결과 검증을 실제 프로젝트 기록에서 확인해 쓴다. [포트폴리오 작성 기준](references/portfolio-writing.md)
- **디자인과 웹 모션.** [원본 선택 또는 후보별 포트폴리오 시안 비교로 확정한 레퍼런스](references/design.md#레퍼런스-선택)를 전체 디자인과 UI 컴포넌트의 기준으로 삼는다. 전송 가능한 원본을 ImageGen의 시각 입력으로 사용해 데스크톱·모바일 시안을 만든다. 시안 이미지와 `docs/art-direction.md`의 승인을 받은 뒤 제작용 파일과 코드를 준비한다. [시안 이미지와 승인](references/design.md#시안-이미지-제작) · [이미지 에셋 제작](references/visual-production.md#이미지-에셋-제작)
- **토큰과 컴포넌트.** `docs/tokens.md`에 기준 색·폰트·간격·표면 효과를 기록한다. 배경 이미지가 필요한 디자인은 최종 레퍼런스를 바탕으로 ImageGen으로 제작하고, 가변 콘텐츠가 담긴 HTML·CSS 컴포넌트는 짧고 긴 상태에서 비교한다. CSS에서 시각 차이가 남으면 필요한 레이어를 ImageGen 에셋으로 제작한다. 승인된 부품과 실제 콘텐츠로 와이어프레임을 조립한다. [토큰과 재사용 컴포넌트](references/component-production.md)
- **시각 검수.** 신규·재설계 섹션은 너비 1440px와 375px의 실제 브라우저 캡처를 승인한 시안 이미지와 기준 레퍼런스 옆에 놓고 채점한다. 실제 글꼴과 색상·구도·에셋이 달라진 곳을 고치고 같은 조건에서 다시 촬영하는 작업을 최소 두 라운드 진행한다. [섹션별 시각 검수](references/review.md#섹션별-시각-검수)

기존 포트폴리오는 바꾸는 화면과 동작에 해당하는 기준을 적용한다.

## 신규 제작의 기본 단계

1. 사용자에게 **GitHub 블로그**와 **HTML 링크** 중 하나를 고르게 한다. GitHub 블로그라면 사용할 저장소를 확인하거나 새 저장소를 준비한 후 프로젝트 기록을 요청한다. HTML 링크라면 프로젝트 기록 단계로 이동한다. [형식 선택과 저장소 준비](references/intake.md#형식-선택과-저장소-준비)를 따른다.
2. 이번 작업에 사용할 프로젝트 기록 경로를 요청하고 답을 기다린다. 사용자가 지정한 경로를 열어 확인한 뒤 발견한 프로젝트 목록을 사용자에게 보여주고 목록 확인만 받는다. 잘못된 경로나 누락이 있으면 자료 위치를 다시 확인한다. 사용자가 목록을 승인하면 진행한다. [프로젝트 기록 확인](references/intake.md#프로젝트-기록-확인)을 따른다.
3. 로컬 디자인 레퍼런스 경로를 우선 요청하고 10장 이상을 권한다. 열어 본 자료의 목록을 제시하고 사용자 확인을 받는다. 잘못된 경로나 누락이 있으면 지정한 폴더에 자료를 넣도록 안내하고 승인받을 때까지 다시 확인한다. [레퍼런스 목록 확인](references/intake.md#레퍼런스-목록-확인)을 따른다.
4. 원본이 많고 선호가 미정이면 HTML 토너먼트로 후보를 좁힌다. 사용자가 번호를 골라 “내 포트폴리오로 먼저 보고 싶다”고 하면 [후보별 비교 시안](references/design.md#후보별-포트폴리오-시안-비교)을 바로 만든다. 이미 하나를 확정했다면 그 원본으로 진행한다. [레퍼런스 선택](references/design.md#레퍼런스-선택)
5. **PM, 웹 기획자, 콘텐츠 에디터, UI 디자이너, 프런트엔드 개발자, QA/배포** 서브 에이전트를 생성한다. [팀 제작 절차](references/production.md)에 연결된 각 역할의 실무 지침과 이번 작업의 승인된 입력·산출물·인계 대상을 해당 에이전트에게 전달한다. PM이 단계마다 산출물과 승인 항목을 정리한다.
6. 첫 화면 메시지와 프로젝트 콘텐츠 후보를 정하고 사용자 선택을 받는다. 최종 레퍼런스로 만든 이미지 시안과 아트 디렉션을 승인받은 뒤 토큰·컴포넌트 목록과 제작용 에셋을 준비한다. 검수한 컴포넌트를 승인 와이어프레임에 배치하고 현재 섹션을 스크린샷으로 비교한다. [단계별 승인](references/production.md#단계별-승인)
7. 실제 브라우저에서 첫 화면에서 대표 상세와 증거까지의 흐름, 원고의 근거, 공개 범위를 검수한다. 사용자 승인 범위에서 선택한 형식의 링크를 제공한다. [검수 가이드](references/review.md) · [최종 링크 제공](references/production.md#최종-링크-제공)

## 승인과 재개

- 이미 해당 단계에 명확하게 답변한 정보는 재사용한다. 질문할 때는 지금 승인할 목록이나 결과물과 사용자에게 필요한 응답을 함께 보여준다.
- 필요한 자료·디자인 선택과 제작 단계 승인은 현재 보여준 결과를 기준으로 한 번에 하나씩 받는다. 시안 확인과 모션 선택은 순서대로 물어본다.
- 사용자가 수정이나 추가를 요청하면 [제작 중 경로 조정](references/routing.md#제작-중-경로-조정)을 따라 영향을 받은 자료·화면·효과와 승인 지점을 확인한다. 수정 결과를 보여주고 그 지점부터 이어간다.
- 작업 유형을 확인한 뒤 단계가 바뀌거나 사용자 응답을 기다리기 전에 작업 폴더의 `.portfolio-crew/progress.md`를 갱신한다. 중간 질문, 다른 작업, 일시 중단으로 대화가 바뀌면 현재 단계와 대기 항목을 저장하고 최신 요청을 처리한다. 사용자가 포트폴리오로 돌아오면 메모에 기록한 지점과 기존 승인을 사용한다. [진행 저장과 재개](references/continuity.md)
